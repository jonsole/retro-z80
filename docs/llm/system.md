# retro-z80: the system

> retro-z80 reference for AI models writing Z80 code. Register tables between `<!-- gen:NAME -->` markers are generated from `fpga/regmap.def` by `python3 tools/llm_docs.py system`: never edit them by hand. Every ```asm block assembles on its own (`python3 tools/llm_docs.py --asm system`; a block without `include "hw.inc"` gets `device zxspectrum48`, `org 0x8000` and the include put in front). The units have files of their own: see [llms.txt](llms.txt).

A Z80 computer in the FPGA of a ZX Spectrum Next. A Z80 (tv80 core) at 20 MHz that never waits for memory, an MMU, and an Amiga-style chipset sharing one SRAM on a fixed slot plan: layers (bitmap or tile-map playfields), sprites, a copper, a descriptor-chain blitter, a line/triangle rasteriser, 4-channel DMA sound, timers, an interrupt controller, keyboards and joysticks, a USB serial link with a debug unit, and a boot ROM with a monitor.

## What is built on the KS2 (the board in use)

The KS2 (XC7A15T) is nearly full, so its bitstream leaves things out. The KS3 is to build everything. Check `fpga/ks2/top_ks2.v` for the current set.

| Unit | KS2 default build | Notes |
|------|-------------------|-------|
| CPU, MMU, register page, boot ROM and monitor | Yes | 2 MB SRAM (`SYSCFG.CHIPMB` = 2) |
| Interrupt controller, TIME, timers, watchdog | Yes | Sources wired: 0–4, 9, 11–15, 17, 18 ([interrupts-timers.md](interrupts-timers.md)) |
| Interrupt pages | NMI set only | The maskable set (IPCTL … IPSAVnW) is not built: reads `0xFF` |
| Video: beam, palettes, BGCOLOR, PRIO | Yes | 720 × 576 at 50 Hz, HDMI and VGA |
| Layers | **L0 only** | L1, L2 registers read `0xFF`. No direct colour (VIDCON.DIRECT does nothing), no attribute layer |
| Sprites | **0 and 1 only** | Sprites 2–7 read `0xFF`. Sprite sequencer not built |
| Copper | Yes | Not in the `build.sh --no-copper` bitstream |
| Blitter | Yes, no 1 bpp mask image | BLTCTRL.MASK = 1 is an error. Not in the `--geom` bitstream |
| Rasteriser | **Lines only** | A triangle job is an error. Not in the `--geom` bitstream |
| Sound | Yes | 4 channels and the beeper |
| Geometry unit | **No** | Only in the `build.sh --geom` bitstream, which drops the blitter and rasteriser ([geometry.md](geometry.md)) |
| Keyboards, joysticks, port `0xFE` | Yes | |
| USB serial, debug unit | Yes | FT232H on the accelerator header |
| SD card, I2C | **No** | Registers read `0xFF` |

A unit, register or page that is not built reads `0xFF` and ignores writes. Nothing ever faults.

## CPU and clocks

| Item | Value |
|------|-------|
| CPU | Z80 (tv80), all documented and undocumented instructions (ZEXDOC/ZEXALL pass). Never waits for memory or I/O |
| Speed | 20 MHz at reset. CPUSPEED (`0x77`): DIV (2–0) gives 20 MHz ÷ (DIV + 1); SPECTRUM (3) gives 3.57 MHz |
| T-states | 640 per video line (32 µs), 400,000 per frame (20 ms) at 20 MHz |
| I/O cycle | 4 T-states; register page access 3 T-states (an ordinary memory cycle); no waits |
| System clock | 100 MHz; memory cycle 20 ns; slot 100 ns = 5 memory cycles = 2 T-states at 20 MHz |
| Video | 720 × 576 picture at 50 Hz (576p), beam 864 × 625; the picture starts at beam pixel 144, line 49 |

## Memory

### MMU

The 64 KB address space is eight 8 KB windows (A15–A13). Each window has a **read page** (fetches and reads) and a **write page**. A page is 10 bits: physical address = page × `0x2000` + (address & `0x1FFF`).

| Page | Meaning |
|------|---------|
| `0x000`–`0x0FF` | SRAM `0x000000`–`0x1FFFFF` (2 MB, the KS2's all) |
| `0x100`–`0x1FF` | SRAM `0x200000`–`0x3FFFFF` (4 MB boards). **On the KS2 these mirror `0x000`–`0x0FF`**: never use them when CHIPMB reads 2 |
| `0x200`–`0x3F7` | Reserved: reads `0xFF`, writes ignored |
| `0x3F8` | **REGS, the register page** (below) |
| `0x3FB` | **NONE**: reads `0xFF`, writes ignored. Use as a write page to make a window read-only |
| `0x3FC`–`0x3FF` | Boot ROM pages 0–3 (writes ignored unless SYSCON.ROMWE) |

Page registers are 2 bytes. **Byte 0 is held; writing byte 1 commits** (the only latched registers besides colours). Committing a read page (MMUn) also sets the window's write page; write MMUnW afterwards to split. Write byte 0 then byte 1: `OUT (C),r` / `INC B` / `OUT (C),r`, or `LD (nn),HL` through the register page; never `PUSH` or `LDDR`. The new map applies from the next access.

### The program map (what a loaded program runs in)

| Window | Addresses | Read page | Write page |
|--------|-----------|-----------|------------|
| 0 | `0x0000`–`0x1FFF` | `0x3FC` boot ROM page 0 | `0x3FC` (writes ignored) |
| n = 1–7 | `0x2000`–`0xFFFF` | SRAM page n | SRAM page n |

So **a Z80 address in `0x2000`–`0xFFFF` is its own physical address**: label `buf` at `0x9000` is physical `0x009000`, and that number goes straight into a layer, sprite, copper, blitter or sound pointer. SRAM page 0 (`0x000000`–`0x001FFF`) is under the ROM and free to map. Programs are assembled with `org 0x8000` and loaded there.

### SRAM the boot ROM keeps

| Pages | Physical | Contents |
|-------|----------|----------|
| `0x0F8`–`0x0FB` | `0x1F0000`–`0x1F7FFF` | Resident image (BASIC, later); free today |
| `0x0FC`–`0x0FD` | `0x1F8000`–`0x1FBFFF` | Loader and debug stub frame buffers while they work; the ROM's sprite demo |
| `0x0FE` | `0x1FC000`–`0x1FDFFF` | Console tile map and console state (hidden map columns 96–127) |
| `0x0FF` | `0x1FE000`–`0x1FFFFF` | Console font (2 KB, PATPT `0x1FE000`), monitor workspace, monitor stack |

A program may use all of SRAM, but **keep out of pages `0x0FC`–`0x0FF` if you want ROM calls, the monitor and the debugger to keep working**. If the monitor finds pages `0x0FE`/`0x0FF` damaged it rebuilds them. The upload of a program is buffered in page `0x0FC`.

### The register page

MMU page `0x3F8` shows every register as memory, in any window. I/O page p, register r is at offset p × 256 + r (the port with its bytes swapped). Custom offset k is at `0x1000` + k. Register-page accesses use no SRAM cycle; an opcode fetch from it reads `0xFF` (`RST 38h`, the trap).

Also: interrupt pages (I/O page `0x01`) at `0x0140`–`0x01FF`, debug unit (page `0x02`) at `0x0200`–`0x023C`. ### Who reaches what

| Area | CPU | Copper | Blitter, rasteriser, sound, display |
|------|-----|--------|--------------------------------------|
| SRAM | Through the MMU | Reads its list | Read/write with 22-bit physical addresses, not through the MMU |
| System page, MMU | Yes | No | No |
| Custom block | Yes | Writes only: MOVE `0x000`–`0x0EF`, MOVR `0x000`–`0x0FF`, MOVEF all | No |
| Boot ROM, register page | Yes | No | No: a physical address wraps into SRAM (bit 21 and up ignored; on the KS2 bit 21 too) |

## Registers

### The port form

Every port is **register (high byte) : page (low byte)**. `OUT (C),r` and `IN r,(C)` put B on A15–A8, so `LD BC,NAME_P` then `OUT (C),A`.

| Page (C) | Contents |
|----------|----------|
| `0x00` | System page: interrupts, key map, timers, serial, SD, input, system, MMU, geometry |
| `0x01` | Interrupt pages (registers `0x40`–`0xFF`) |
| `0x02` | Debug unit |
| `0x10`–`0x13` | Custom block: **offset k → port ((k & `0xFF`) << 8) \| (`0x10` + (k >> 8))** |
| others | Reserved: read `0xFF` |

Five **low-byte-only ports** ignore the high byte, so `IN A,(n)`, `OUT (n),A`, `INIR` and `OTIR` work on them:

|------|------|------|
| `0x1F` | `0x1F` | `KEMPSTON_PORT` |
| `0x53` | `0x53` | `SERDATA_PORT` |
| `0x5B` | `0x5B` | `SDDATA_PORT` |

| `0xFE` | `0xFE` | `ULA_PORT` |

| Instruction | A15–A8 | Use |
|-------------|--------|-----|
| `OUT (C),r` / `IN r,(C)` | B | The normal way. `INC B` steps to the next register (next byte of a wide one) |
| `IN A,(n)` | A | `LD A,register` / `IN A,(page)` reads a register: `ld a,INTID` / `in a,(SYSPAGE)` |
| `OUT (n),A` | A | Useless on pages (A is both data and register); fine on the low-byte-only ports |
| `OTIR`, `INIR` | B = count | Only on the low-byte-only stream ports. On a page they step registers **downwards**; unrolled `OUTI` writes a table held high byte first |

### hw.inc names

`firmware/include/hw.inc` is generated from `fpga/regmap.def`; use its names, never raw numbers.

| Name | Meaning | Example |
|------|---------|---------|
| `NAME` | System register number, or custom offset (also its register-page offset; custom: `REGS_CUSTOM + NAME`) | `VIDCON` = `0x000`, `SYSID` = `0x70` |
| `NAME_P` | The port | `ld bc,VIDCON_P` |
| `NAME_N` | Width in bytes | `BGCOLOR_N` = 3 |
| `NAMEk`, `NAMEk_P` | Byte k of a wider register (`NAME_k` where NAME ends in a digit or digit+letter) | `BGCOLOR2_P`, `MMU7_1_P`, `L0_BPL0PT2_P`, `TMR0_COUNT0` |
| `NAME_F_B`, `_W`, `_M` | Field F's lowest bit, width, mask **in the whole value** (shift a mask right 8k for byte k) | `DMACON_BLTEN_M` = `0x08`, `BLTCTRL_BPP_M` = `0x300` |
| `Gn`, `Gn_REG`, `Gn_REG_P`, `G_REG`, `G_NUM`, `G_SPAN` | Arrays (L, SPR, TMR, AUD, MMU, DBGBP …) | `SPR1_CTL_P`, `L0_SCROLLX_P`, `AUD0_CTRL` |
| `INT_x`, `INTR_x`, `INTB_x` | Interrupt source number, INTENA byte, bit | `INT_VBLANK`, `INTR_AUDIO` = 1 |
| `REGS_x` | Register-page offsets | `REGS_CUSTOM`, `REGS_PALETTE` |

sjasmplus has no function-like macros: for a computed custom port write `((off & 0xFF) << 8) | 0x10 | (off >> 8)`. Adding `k << 8` to a custom `_P` steps k bytes only while (offset & `0xFF`) + k stays below `0x100`.

### Register rules

| Rule | |
|------|---|
| Wide values | Consecutive bytes, **low byte first**. No latches: each byte takes effect when written, in any order. Change wide display registers in the vertical blank or from the copper |
| Exceptions | MMU and interrupt pages commit on byte 1. Colours (BGCOLOR, PALDAT, register-page palettes) commit on the **red** byte (blue, green, red: rising addresses). Captures (below) |
| Captures (CAP) | Reading the **low byte** of a counter the hardware changes captures the whole value; its higher bytes then read from the capture. One capture for the CPU: an interrupt handler reading another CAP register replaces it. CAP registers: BEAMPOS, FRAMECOUNT, Ln_BPL0PT, SPRn_PT, COPPC, SEQPT, BLTDESC, RASDESC, TIME, TMRn_COUNT, SDCOUNT, AUDn_POS |
| W1C | Sticky flags: write 1 to clear. Write back the value read to clear exactly what was seen |
| SC (set/clear) | DMACON, INTENA0–2, AUDDMA; SPRDMA (SETCLR in its 2nd byte). Bit 7 = SETCLR: 1 sets the bits written as 1, 0 clears them. **Never read-modify-write** |
| S (strobe) | Any write acts (COPJMP1/2, COPINT, BLTCMD, RASCMD, AUDSTART/STOP …). SYSRESET needs `0xA5`, WDKICK `0x5A` |
| Reading | No side effects except SERDATA, KBDATA (take a byte), SERDROP (clears), PALDAT red byte (steps the index), SDDATA with AUTO, and the captures |
| Unused | Unused offsets, pages and unbuilt units read `0xFF`; write-only registers read `0x00`; reserved bits read 0, write 0 |
| BUSY | Blitter and rasteriser job registers ignore writes while their unit is busy |
| No BPLxDAT | There are no layer data registers (no BPLxDAT, no BPLDMA): a layer cannot be fed by the CPU or copper |

## The boot ROM and a program's environment

At reset the MMU maps ROM pages 0–1 in windows 0–1 and SRAM pages 0–5 in windows 2–7; the ROM tests memory (power-on only), sets up the 80 × 30 console on layer L0 and runs the monitor. A program started by an upload (the MCP `launch`, `rlink.py upload`, VS Code) starts with:

| Item | State |
|------|-------|
| PC | The entry (normally the load address, `0x8000`) |
| SP | `0xFFFE`; the word there is `0x0040` (EXIT), so `RET` from the entry ends the program |
| Registers | All 0, alternates too |
| Interrupts | **DI**, IM 2, I = `0x1F`, VECBASE = `0xD0` (the ROM's table at `0x1FD0`, whose one handler turns off whatever source fires). INTENA clear, INTCON.MASTER clear |
| NMI | On: the Multiface button and the PC's BREAK enter the monitor (the debugger's pause) |
| CPU speed | 20 MHz |
| MMU | The program map |
| Video | L0 = the console (1 bpp tile map, MAPPT `0x1FC000`, PATPT `0x1FE000`, 640 × 480 window); sprites off; BGCOLOR black; PALETTE0 entries 0–15 the Spectrum colours; colour pair p (0–14) is entries 16(p + 1) and 16(p + 1) + 1. DMACON: DMAEN, BPLEN |
| Copper, blitter, rasteriser, sound | Stopped |
| Timers | Stopped; watchdog off; TIME counting |
| Serial | SERCON = EN, CTLEN, TXDROP; no interrupts |

### ROM calls (window 0 must hold ROM page 0)

| Call | In | Out |
|------|----|-----|
| `RST 08h` PUTC | A = character | A kept. 13 = column 0, 10 = new line (send both), 12 = clear |
| `RST 10h` GETC | – | A = key code (waits) |
| `RST 18h` PUTS | HL = string ending in 0 | HL past the 0 |
| `RST 20h` POLLC | – | NZ, A = key; Z, A = 0 if none |
| `RST 28h` + `db n` | Function n (below) | As the function says; carry + A = error |
| `RST 30h` BREAK | – | Enters the monitor (a breakpoint by hand) |
| `JP 0x0040` EXIT | – | Ends the program from anywhere, whatever SP holds |

`RST 28h` functions: `0x00` VERSION, `0x05` GETLINE (HL = buffer, B = size), `0x06` PUTHEX (A), `0x07` PUTHEX16 (HL), `0x08` PUTDEC (HL), `0x09` CLS, `0x0A` SETPOS (H = row 0–29, L = column 0–79), `0x0B` GETPOS, `0x0C` SETPAIR (A = colour pair 0–14), `0x0D` PUTRAW, `0x0E` CONMODE, `0x0F` EXIT, `0x10` BREAK, `0x11` RESET. `0x12`–`0x14` (SD card) are not there. Calls keep every register but F and their outputs, use up to 48 bytes of stack, work with interrupts on (off for at most about 150 µs), and borrow window 4 (or 2) for a moment: the caller's code, stack and strings may be anywhere in `0x2000`–`0xFFFF`. Key codes: 8 Backspace, 13 Enter, 27 Esc, 32–126 characters, 136–139 Left/Right/Down/Up, 145–156 F1–F12.

### Ending a program

| How | Result |
|-----|--------|
| `RET` with SP back at `0xFFFE` | "Program ended.", the monitor |
| `JP 0x0040`, or `RST 28h` / `db 0x0F` | The same, whatever SP holds. Use this after moving the stack |
| `RST 30h` | "Break at": `G` (or the MCP `run`) continues after it |
| A fetch of `0xFF` (runaway into NONE, the register page or empty memory) | "Trap RST 38h at addr" |
| `RST 28h` / `db 0x11`, or SYSRESET `0xA5` | A full reset |

### A minimal program

```asm
; Prints a line, sets the border red, waits for a key and returns to the monitor.
        device  zxspectrum48            ; sjasmplus writes --sld lines only inside a DEVICE
        org     0x8000
        include "hw.inc"

start:  ld      hl,msg
        rst     0x18                    ; PUTS
        ld      bc,BGCOLOR0_P           ; blue, green, then red commits
        xor     a
        out     (c),a                   ; blue
        inc     b
        out     (c),a                   ; green
        inc     b
        ld      a,0xFF
        out     (c),a                   ; red: the colour changes now
        rst     0x10                    ; GETC: wait for a key
        ret                             ; SP is 0xFFFE: back to the monitor
msg:    db      "Hello from retro-z80", 13, 10, 0
```

### Interrupts

One /INT line, IM 2, fixed priority by source number (lower first). Vector = VECBASE + 2 × source; the table is at I × 256 + VECBASE (24 two-byte entries, VECBASE even). A request is **level-sensitive**: the handler must clear the cause (usually a W1C flag) before `EI` / `RETI`. Enable chain: the unit's own enable, INTENA (set/clear byte `INTR_x`, bit `INTB_x`), INTCON.MASTER, then `EI`. Details and recipes: [interrupts-timers.md](interrupts-timers.md).

## Memory cycles, DMA and the slot budget

Every 100 ns slot has 5 memory cycles of 20 ns, each one 16-bit SRAM access. The plan is fixed:

| Cycle | Owner | Others get it when the owner leaves it |
|-------|-------|----------------------------------------|
| 0, 2 | CPU (locked: never taken from it) | Yes |
| 1, 3 | Display: layers and sprites, earliest deadline first | Yes |
| 4 | Sound | Yes |

Free cycles go by priority: urgent display, then layers, sprites, sound, copper (first if COPCON.PRI ≠ 0), CPU, blitter, rasteriser. Budget per 576p line (320 slots): display 1,280 bytes (1.48 bytes per pixel of the 864-pixel line); free pool at least 747 cycles (about 47 MB/s), more in the vertical blank (49 lines with no display fetch).

- **DMACON** (custom `0x00C`, set/clear) turns memory users on: DMAEN (all), BPLEN (layers), COPEN, BLTEN (blitter and rasteriser), SPREN, AUDEN (with AUDDMA per channel). The monitor leaves DMAEN and BPLEN on for the console. Write `DMACON_SETCLR_M | bits` to set, `bits` alone to clear.
- **Chipset pointers are physical** byte addresses (22 bits; on the KS2 bit 21 is ignored too). Pointers named `ADDR=21:1` (layers, sprites, sequencer, attribute layer) are **even**; copper lists are even; the blitter and rasteriser take byte (and bit) addresses; their descriptors are even (examples use `align 4`); sound blocks are even for 16-bit samples.
- A screen over the display budget shows late data (VIDSTAT.OVERRUNn); the CPU is never slowed.

## Running on the board: the MCP bridge

`tools/rz80_bridge.py` owns the board's serial port and serves MCP at `http://127.0.0.1:8780/mcp` (and DAP for VS Code, at the same time: the user may be watching). `tools/rz80_mcp.py` is a stdio front that adopts a running bridge or starts one (`RLINK_PORT=COM3`). ## Pitfalls

1. **A runaway write over SRAM wedges the board and its link.** If a loop overwrites pages `0x0FC`–`0x0FF` (the monitor, the link's buffers), BREAK, RESET and uploads stop working; only a power cycle (and a bitstream reload) recovers it. Check every loop's exit test before running it: `LDI`/`LDIR` change BC and P/V; `AND`, `OR`, `XOR`, `CP` change P/V. Bound buffers; keep clear of `0x1F8000` up.
2. **Wrong build assumptions.** On the KS2 only L0 and sprites 0–1 exist, the rasteriser draws no triangles, the blitter has no mask image, there is no geometry unit, SD card or I2C. Writes to them vanish; reads give `0xFF`.
3. **Pages `0x100`–`0x1FF` and physical `0x200000` up mirror the bottom 2 MB on the KS2**, onto the console and monitor pages.
4. **Window 7 holds the stack** (SP `0xFFFE`). Move SP before mapping something else there, then end with `JP 0x0040`, not `RET`.
5. **`OUT (n),A` and `OTIR` on a page** do not do what they seem: use `OUT (C),r` with `LD BC,NAME_P`.
6. **`IN A,(n)` puts A on the high byte**: load A with the register number first. Reads of SERDATA, KBDATA, PALDAT's red byte and CAP low bytes have side effects; the MCP `read_memory` hides them unless `side_effects: true`.
7. **Colours commit on red; MMU pages on byte 1.** Write in rising order; never `PUSH`/`LDDR` them.
8. **Set/clear registers** (DMACON, INTENA, AUDDMA, SPRDMA): write only the bits to change, with SETCLR; never read-modify-write.
9. **Level-sensitive interrupts:** clear the source's flag in the handler or it re-enters at once. The ROM's default table turns off any source that fires, so set up your own table before enabling sources.
10. **Captures are shared:** a handler that reads a CAP register (TIME0, BEAMPOS …) spoils a main-program read in progress. Read with interrupts off, or through the register page with `LD HL,(nn)`.
11. **Wide display registers are not latched:** a pointer or scroll changed mid-frame may be seen half written. Change them in the vertical blank or from the copper.
12. **No layer data registers:** BPLxDAT and BPLDMA do not exist; the CPU cannot feed a layer.
13. **The register page fetch trap:** jumping into the register page, NONE or unwritten memory executes `0xFF` = `RST 38h` and stops in the monitor ("Trap").
14. **SPRxCTL starts a sprite and the vertical blank stops every sprite**: rewrite CTL every frame (the copper does this best).
15. **Blitter/rasteriser job registers ignore writes while BUSY**; wait for BLTSTAT/RASSTAT.BUSY = 0 before loading the next job.
