# Rasteriser

> retro-z80 reference for AI models writing Z80 code. Register tables between `<!-- gen:NAME -->` markers are generated from `fpga/regmap.def` by `python3 tools/llm_docs.py rasteriser`: never edit them by hand. Every ```asm block assembles on its own (`python3 tools/llm_docs.py --asm rasteriser`); general rules are in [system.md](system.md).

**Built on the KS2:** lines only (`DMX_TRI 0`): a TRI job is an **error** there (RASSTAT.ERR, nothing drawn, chain ends). Triangles on the KS3. Not in the KS2's `--geom` build (`DMX 0`: registers read `0xFF`, always idle).

## What it does

Draws lines (LINE) and flat-filled triangles (TRI) into a bitmap in SRAM from signed 16-bit screen coordinates, clipped to a window in hardware. Each pixel D = MINTERM(A, B, C): A a 16-bit line pattern bit (1 in a triangle), B the constant colour VALUE, C the old pixel. Programmed like the [blitter](blitter.md): job registers laid out as a 32-byte descriptor, chains, START/RUN/STOP. A separate unit: it runs at the same time as the blitter. Free memory cycles only; the Z80 never waits.

## Enable

| Need | Write |
|------|-------|
| Memory cycles | DMACON.DMAEN and DMACON.BLTEN (shared with the blitter; no bit of its own) |
| Clip window | RASCLIPMIN, RASCLIPMAX: **must be set**; reset value is 0, 0 to 0, 0 (one pixel) |
| Interrupt (optional) | DMXINTEN.RAS, INTENA bit for source 4 (`INT_BLT`, shared with the blitter), INTCON.MASTER, IM 2 |

- Custom block, page `0x11` (port `(offset & 0xFF) << 8 | 0x11`); register page offset + `0x1000`. `INC B` steps through the bytes.
- Job registers `0x180`–`0x19F`, RASDESC and the clip window: **writes ignored while BUSY**. Job registers and the window are not reset (0 after power-on).
- Bytes `RASDPT3`, `RASSTRIDE2`/`3`, `RASPAT2`/`3`, `RASNEXT3` hold no bits: read 0.
- RASCTRL's reserved bits (23–18, 15–13, 11–10) are stored but read 0, and **a job with any of them set is an error** (unlike the blitter, which ignores its reserved bits). So a blitter descriptor given to the rasteriser by mistake is usually refused.
- RASDESC: 3 bytes, bit 0 and bits 23–22 not kept; reading `RASDESC0` captures all three.
- RASCMD (strobe, reads 0): START (0) loads the descriptor at RASDESC and runs; RUN (1) runs the registers as they are; START wins; both ignored while BUSY. STOP (2) ends after the pixel (LINE) or row (TRI) in hand, chain not followed.
- RASSTAT: BUSY (0) set by the START/RUN write itself; ERR (2) cleared by the next START/RUN.
- DMXINT.RAS (bit 1): set at the end of a job with IRQ and whenever the rasteriser stops (chain end, STOP, error). W1C. Source 4, IM 2 vector VECBASE + 8; the handler reads DMXINT to see BLT (bit 0) or RAS (bit 1).

### RASCTRL

| Bits | Byte | Field | Meaning |
|------|------|-------|---------|
| 31–24 | RASCTRL3 | MINTERM | D bit = MINTERM bit number (4·A + 2·B + C), as the blitter |
| 17 | RASCTRL2 | NOLAST | LINE: don't draw point 1 (joined lines don't draw corners twice) |
| 16 | RASCTRL2 | TRI | 0 = LINE, 1 = TRI (**error on the KS2**) |
| 12 | RASCTRL1 | IRQ | Set DMXINT.RAS when this job ends |
| 9–8 | RASCTRL1 | BPP | 0 = 1, 1 = 2, 2 = 4, 3 = 8 bits per pixel |
| 7–0 | RASCTRL0 | VALUE | The colour B, in its low BPP bits. One pixel's colour: no byte-order issue (colour 5 is 5 at any depth) |

Points: RASPn = Y in bits 15–0, X in bits 31–16, both signed. In memory `dw y, x` (Y first). RASDPT: physical byte of pixel (0, 0); row y starts at RASDPT + y × DSTRIDE (signed). Pixels packed from the most significant end of each byte. Negative coordinates are real addresses (before pixel 0,0): only the window keeps writes inside the bitmap.

## Data structures

<!-- gen:raster-desc -->

Descriptor (32 bytes, little-endian words; the same layout as `RASCTRL`…`RASNEXT`):

| Byte | Word | Register | Byte 3 (bits 31–24) | Byte 2 (23–16) | Byte 1 (15–8) | Byte 0 (7–0) |
|------|------|----------|---------------------|----------------|---------------|--------------|
| +0 | 0 | `RASCTRL` | MINTERM 7–0 | NOLAST 1, TRI 0 | IRQ 4, BPP 1–0 | VALUE 7–0 |
| +4 | 1 | `RASP0` | X[31:24] | X[23:16] | Y[15:8] | Y[7:0] |
| +8 | 2 | `RASP1` | X[31:24] | X[23:16] | Y[15:8] | Y[7:0] |
| +12 | 3 | `RASP2` | X[31:24] | X[23:16] | Y[15:8] | Y[7:0] |
| +16 | 4 | `RASDPT` | 0 | ADDR[23:16] | ADDR[15:8] | ADDR[7:0] |
| +20 | 5 | `RASSTRIDE` | 0 | 0 | DSTRIDE[15:8] | DSTRIDE[7:0] |
| +24 | 6 | `RASPAT` | 0 | 0 | PATTERN[15:8] | PATTERN[7:0] |
| +28 | 7 | `RASNEXT` | 0 | ADDR[23:16] | ADDR[15:8] | ADDR[7:0] |

`NAME h–l`: the field in bits h–l of that byte. `NAME[h:l]`: bits h–l of a field wider than the byte (whole-word numbering). Bits not named are reserved: write 0.
<!-- /gen:raster-desc -->

- 32 bytes at an **even** physical address; the same layout as the job registers. RASNEXT = 0 ends the chain. The clip window is **not** in the descriptor: one window per chain.
- sjasmplus: `dd ctrl` / `dw y0, x0, y1, x1, y2, x2` / `dd dpt, stride, pattern` / `dd next`.

### What is drawn

| Job | Rule |
|-----|------|
| LINE | Bresenham from P0 to P1, one pixel a step along the longer axis, error term starting at major/2. Both ends drawn unless NOLAST. P2 ignored. PATTERN bit 15 is A for the first pixel, then bit 14, … going round; it advances for every pixel stepped, written or not. `0xFFFF` = solid |
| TRI (KS3) | Points in any order. Rows from the top y up to, not including, the bottom y; span pixels `ceil(XL) <= x < ceil(XR)` (16.16 edges). Shared edges filled exactly once (safe with XOR); bottom row and right edge left to neighbours; zero area draws nothing. A = 1, PATTERN ignored |
| Clip | Only pixels with XMIN ≤ x ≤ XMAX and YMIN ≤ y ≤ YMAX (inclusive) are written. XMAX < XMIN or YMAX < YMIN draws nothing |

| MINTERM | D = | Use |
|---------|-----|-----|
| `0xCC` | B | Solid colour (pattern has no effect) |
| `0xCA` | A ? B : C | Dashed line over the picture |
| `0xC0` | A ? B : 0 | Dashed line on colour 0 |
| `0x66` | B XOR C | Draw and undraw with the same job (use NOLAST for polylines) |
| `0xEE` / `0x88` | B OR C / B AND C | Set / keep bits |
| `0x55` | NOT C | Invert |

## Recipes

Set the clip window to a 360 × 288 bitmap (YMIN, XMIN, YMAX, XMAX), once:

```asm
W       equ     360
H       equ     288
setclip: ld     hl,clipw
        ld      bc,RASCLIPMIN0_P        ; 8 bytes: 0x1AC..0x1B3, C = 0x11
.cl:    ld      a,(hl)
        out     (c),a
        inc     hl
        inc     b
        ld      a,b
        cp      high (RASCLIPMIN0_P + 0x0800)
        jr      nz,.cl
        ret
clipw:  dw      0, 0, H - 1, W - 1      ; YMIN, XMIN, YMAX, XMAX
```

Draw one line with RUN, after RASCTRL, RASDPT, RASSTRIDE, RASPAT and RASNEXT (= 0) are already set: only the two points change. HL points at `dw y0, x0, y1, x1`.

```asm
line:   ld      bc,RASSTAT_P
.idle:  in      a,(c)
        rra                             ; BUSY into carry
        jr      c,.idle
        ld      b,high RASP0_P          ; RASP0 then RASP1: 8 bytes
.next:  ld      a,(hl)
        out     (c),a
        inc     hl
        inc     b
        ld      a,b
        cp      high RASP2_P
        jr      nz,.next
        ld      b,high RASCMD_P
        ld      a,RASCMD_RUN_M
        out     (c),a
        ret                             ; HL now points at the next line
```

A chain of line descriptors started with RASDESC + START (adapted from `examples/blitter/raster.asm`, lines only so it runs on the KS2). In the program map a label is its own physical address:

```asm
SCREEN  equ     0x020000
W       equ     360
    MACRO RJOB ctl, x0, y0, x1, y1, pat, nxt
        dd      ctl
        dw      y0, x0, y1, x1, 0, 0    ; P0, P1; P2 unused by LINE
        dd      SCREEN, W, pat
        dd      nxt
    ENDM
B8      equ     3 << RASCTRL_BPP_B
MT      equ     1 << RASCTRL_MINTERM_B  ; MINTERM x: x * MT; colour in bits 7-0

go:     ld      bc,RASDESC0_P
        ld      a,low job1
        out     (c),a
        inc     b
        ld      a,high job1
        out     (c),a
        inc     b
        xor     a
        out     (c),a
        ld      bc,RASCMD_P
        ld      a,RASCMD_START_M
        out     (c),a
        ld      bc,RASSTAT_P
.wait:  in      a,(c)
        rra
        jr      c,.wait
        and     RASSTAT_ERR_M >> 1      ; NZ: error (a TRI job on the KS2, a reserved bit)
        ret

        align   4
job1:   RJOB    B8|0xCC*MT|3, 280, 140, 350, 140, 0xFFFF, job2       ; white, solid
job2:   RJOB    B8|0xCA*MT|4, 20, 262, 340, 248, 0xF0F0, job3        ; yellow, dashed
job3:   RJOB    B8|0xCC*MT|6, -2000, 20, 2400, 34, 0xFFFF, 0         ; clipped at both ends
```

A filled triangle (KS3 only; an error on the KS2): `RASCTRL = (0xCC << 24) | RASCTRL_TRI_M | (3 << 8) | colour`, `dw y0,x0, y1,x1, y2,x2`. A convex polygon of n corners is a fan of n − 2 triangles.

## Pitfalls and limits

- **TRI is not built on the KS2**: a TRI job stops with ERR and ends its chain at that job. Check RASSTAT.ERR. On the KS2, fill shapes with the blitter or with CPU spans.
- **Set the clip window first**; it is the only thing keeping writes inside the bitmap. Reset leaves it at the single pixel (0, 0).
- SRAM only, **physical addresses**, no range check (see [blitter.md](blitter.md) and system.md). Bit 21 ignored on the KS2.
- Writes to job registers, RASDESC and the window are **ignored while BUSY**.
- Every pixel of a line is stepped even outside the window (20 ns each): an end at ±32,767 costs up to 1.3 ms. Cut very long lines roughly in software first.
- With a minterm that reads C (XOR), joined lines double their shared corner: use NOLAST.
- A line and the same line reversed may differ by one pixel on a tie.
- Blitter and rasteriser run concurrently with unspecified order where they overlap: wait for a blitter clear (BLTSTAT.BUSY) before drawing over it.
- Time, measured on the KS2 (screen off): a line pixel about 110 ns with minterm 0xCC, 177 ns with XOR; a pixel stepped outside the clip window about 10.6 ns (a 300-pixel line 33 µs, a 64,001-pixel line 678 µs). From the design: descriptor load about 1 µs, set-up 0.25 µs; a triangle about 1.5 µs before its first row, then fill at up to about 25 MB/s at 8 bpp.
- The copper writes these registers with MOVEF; a copper WAIT with B waits for both rasteriser and blitter to be idle.
