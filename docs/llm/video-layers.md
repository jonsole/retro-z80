# Video and layers

> retro-z80 reference for AI models writing Z80 code. Register tables between `<!-- gen:NAME -->` markers are generated from `fpga/regmap.def` by `python3 tools/llm_docs.py video-layers`: never edit them by hand. Every ```asm block assembles on its own (`python3 tools/llm_docs.py --asm video-layers`); general rules are in [system.md](system.md).

**Built on the KS2:** the beam, BGCOLOR, palettes, PRIO, VIDSTAT/VIDINTEN, BEAMPOS/FRAMECOUNT/LINECMP and **layer L0 only** (bitmap or tile map). L1 and L2 are not built: their registers read `0xFF` and ignore writes, and PRIO naming them shows nothing. Not built anywhere yet: direct colour (VIDCON.DIRECT reads back, does nothing) and the attribute layer (`0x130`–`0x13F` read `0xFF`). The KS3 build is to have all three layers.

## What it does

576p (720 × 576, 50 Hz) on HDMI and VGA. Up to three layers L0–L2, each a chunky **bitmap** or a **tile map** of 8 × 8 tiles, 1/2/4/8 bits per pixel, scaled 1×/2×/4×/8× across and down, in its own window, fetched just in time from SRAM (no line buffers). Four 256-entry 24-bit palettes (PALETTE0–2, SPRPALETTE), a background colour, layer priority, sprites (see [sprites.md](sprites.md)) among the layers.

## Enable

| What | Needs |
|------|-------|
| The beam (sync, VBLANK, LINE) | VIDCON.EN (the boot ROM leaves it on) |
| A layer fetched | VIDCON.EN, DMACON.DMAEN, DMACON.BPLEN, Ln_CTRL0.EN, and its window covering the line |
| A layer shown | Also named in PRIO (reset `0x24`: L0 front, L1 middle, L2 back) |

The program inherits L0 as the boot console (1 bpp tile map, MAPPT `0x1FC000`, PATPT `0x1FE000`, window 640 × 480 at beam (184, 97)), DMAEN and BPLEN on. Reprogramming L0 replaces the console; the monitor rebuilds it when the program ends.

## Beam coordinates

All positions (windows, sprite windows, LINECMP, BEAMPOS, copper WAIT) are **beam** coordinates, blanking included.

| | Across (pixel) | Down (line) |
|--|--|--|
| Blank | 0–143 | 0–48 (vertical blank) |
| Picture | 144–863 | 49–624 |
| Total | 864 | 625 |

Pixel clock 27 MHz (37 ns a pixel); a line is 32 µs = 640 T-states at 20 MHz; a frame 20 ms. Line 0, pixel 0 = start of the vertical blank = VBLANK event = copper restart. The first picture line (49) is fetched from (49, 0), so a VBLANK handler has 49 lines (1.57 ms) to set up a frame.

- **VIDCON:** EN starts the beam (clearing it stops sync: the monitor loses the picture); BLANKALL shows BGCOLOR only; SHAREPAL puts every layer and sprite on PALETTE0; DIRECT not built.
- **VIDSTAT:** sticky W1C flags; INVBLANK (bit 3) is live, 1 in lines 0–48. VBLANK sets at (0, 0); LINE at pixel 0 of beam line LINECMP (above 624: never). OVERRUN0–2: a layer's group was late; SPRUNDER: a sprite FIFO ran dry. Clear by writing back the bits read.
- **VIDINTEN:** level request while flag and enable are set. VBLANK → interrupt source 0, LINE → 1, OVERRUNn/OVERRUNA/SPRUNDER → 3 (VIDERR). See [interrupts-timers.md](interrupts-timers.md).
- **BGCOLOR:** blue, green, red; the **red byte commits** all three (blue and green wait in the writer's colour assembly buffer). Shown from the start of a line's picture (pixel 144). A port `0xFE` write sets it to a Spectrum colour at once, mid-line.
- **PALIDX/PALDAT:** see Palettes. **DMACON:** set/clear (bit 7 SETCLR); write only the bits to change, never read-modify-write.
- Reset: everything 0 except PRIO `0x24` and the windows (full screen).

## Data structures

**Chunky pixels** (bitmaps and tile patterns): d = 1/2/4/8 bits a pixel, packed in bytes, **leftmost pixel in the highest bits**, bytes left to right at rising addresses. Lines are `BPLSTRIDE` bytes apart.

| BPP | Bits | Pixels a byte | Colours |
|-----|------|---------------|---------|
| 0 | 1 | 8 | 2 |
| 1 | 2 | 4 | 4 |
| 2 | 4 | 2 | 16 |
| 3 | 8 | 1 | 256 |

**Tile map entry**, 2 bytes, low byte first, entry (c, r) at `MAPPT + (r × MW + c) × 2`:

| Byte | Bits 7–0 |
|------|----------|
| 0 | TILE bits 7–0 |
| 1 | 7 PRI, 6 YFLIP, 5 XFLIP, 4–1 PAL 3–0, 0 TILE bit 8 |

<!-- gen:map-entry -->
<!-- Generated by tools/llm_docs.py from fpga/regmap.def; do not edit by hand. -->
| Name | Value | Meaning |
|------|-------|---------|
| `ME_TILE8` | 1 | Map entry high byte: TILE bit 8 (tiles 256-511) |
| `ME_PAL_B` | 1 | Map entry high byte: PAL is bits 4-1, (pal << ME_PAL_B) |
| `ME_PAL_M` | `0x1E` | Map entry high byte: PAL's mask |
| `ME_XFLIP` | `0x20` | Map entry high byte: the tile mirrored left to right |
| `ME_YFLIP` | `0x40` | Map entry high byte: the tile upside down |
| `ME_PRI` | `0x80` | Map entry high byte: in front of all layers |
<!-- /gen:map-entry -->

PRI: the tile's pixels go in front of all layers and of sprites with DEPTH 1–3. **Tile t**, row y (0–7) is at `PATPT + t × 8d + y × d` (d = bits per pixel): 8 bytes a tile at 1 bpp, 64 at 8 bpp; up to 512 tiles.

Tile scroll: on window source line n the map line is `(SCROLLY + n) mod (8 × MH)`; across, map pixel `(SCROLLX + i) mod (8 × MW)`. The map wraps both ways.

**Palette index** a layer pixel p uses (within the layer's own palette, or PALETTE0 with SHAREPAL):

| Layer | d ≤ 4 | d = 8 |
|-------|-------|-------|
| Bitmap | PALOFS × 16 + p | p |
| Tile map | ((PALOFS + PAL) mod 16) × 16 + p | p |

A 1-bit layer uses the first two entries of its block.

**Palette entry:** 3 bytes, blue, green, red. Palettes are not cleared by reset; at configuration all four hold the Spectrum colours in entries 0–15 (0 black, 1 blue `0x0000D7` … 7 white `0xD7D7D7`, 8–15 bright) and black in 16–255. The boot ROM sets PALETTE0 entries 16–47 for the console's colour pairs.

| Palette number (PALIDX bits 9–8) | Register page offset | Used by |
|---|---|---|
| 0 | `0x1400` | L0 |
| 1 | `0x1700` | L1 |
| 2 | `0x1A00` | L2 |
| 3 | `0x1D00` | Sprites (SPRPALETTE) |

Entry i of palette p is at register page offset `0x1400 + p × 0x300 + 3i` (`REGS_PALETTE`, `REGS_PAL_SPAN`).

**Priority**, back to front: BGCOLOR; DEPTH-3 sprites; PRIO.BACK layer; DEPTH-2 sprites; PRIO.MIDDLE; DEPTH-1 sprites; PRIO.FRONT; PRI tile pixels; DEPTH-0 sprites. PRIO fields hold a layer number 0–2; 3 names none.

## When writes take effect

| Registers | Take effect |
|-----------|-------------|
| CTRL0.EN, MODE, CTRL1.VSCALE, CTRL3, WINX, WINY, SCROLLX, SCROLLY, MAPPT, PATPT | At beam pixel 0 of each line: to change line L, write during line L − 1 or earlier |
| CTRL0.BPP, HSCALE | From the next 16-pixel group the fetch starts |
| CTRL0.TRANSP, CTRL1.PALOFS, VIDCON, palette entries | At once (next pixel) |
| BPL0PT, BPLSTRIDE | Live. BPLSTRIDE is used at the end of each line |
| PRIO, BGCOLOR | At the start of each line's picture (pixel 144) |
| LINECMP, VIDSTAT, VIDINTEN, PALIDX, DMACON | At once |

No latches: each byte acts when written, so change wide registers (pointers, windows, scroll) in the vertical blank or from the copper at a set position.

**BPL0PT moves.** Each word fetched adds 2. At the end of each line (pixel 0) the pointer becomes that line's start + BPLSTRIDE (on all but the last copy of a vertically scaled line, it goes back to the line's start). **Nothing resets it at the frame start: rewrite BPL0PT every frame** (VBLANK handler or copper), all three bytes, while the layer is not fetching.

## Palettes

Through ports: write PALIDX (byte 0 entry, byte 1 palette 0–3; either write resets the byte counter), then PALDAT blue, green, red per entry; the red write commits and steps the index (255 of one palette → 0 of the next). Do not use `OTIR` (it decrements B, the register number). The CPU and the copper each have their own PALIDX, byte counter and colour buffer.

Through the register page: map MMU page `0x3F8` in a window ([system.md](system.md)); entry bytes are blue, green, red at rising addresses; red commits. `LDIR` works (rising), `LDDR` does not. PALIDX is not used.

## Fetch budget

The display's own cycles give **1.48 bytes per pixel** at every point across the screen; layers and sprites over the same pixel must fit in it (spare CPU and audio cycles usually add more).

| Layer | Bytes per screen pixel |
|-------|------------------------|
| Bitmap, d bpp | d ÷ 8 ÷ HSCALE factor |
| Tile map 1 or 2 bpp | 0.5 ÷ HS |
| Tile map 4 bpp | 0.75 ÷ HS |
| Tile map 8 bpp | 1.25 ÷ HS |

Vertical scaling saves nothing (each source line is fetched again per screen line). Examples: 8 bpp bitmap at 1× = 1.0 (fits); 8 bpp tiles at 1× = 1.25 (fits); two 8 bpp bitmaps at 1× = 2.0 (does not). A late group shows transparent pixels and sets OVERRUNn; the CPU is never slowed.

## Recipes

Wait for the vertical blank by polling (interrupts off):

```asm
vbl:    ld      bc,VIDSTAT_P
        ld      a,VIDSTAT_VBLANK_M
        out     (c),a                   ; clear the sticky flag
.wait:  in      a,(c)
        and     VIDSTAT_VBLANK_M
        jr      z,.wait                 ; set again at beam (0,0)
        ret
```

L0 as an 8 bpp bitmap, 360 × 288 at 2 × 2, full screen, from a table of (port, value) pairs. `SCREEN` is a physical SRAM address (here SRAM page `0x10` upward, 103,680 bytes, outside the program map: map it into a window to draw, see [system.md](system.md)).

```asm
SCREEN  equ     0x020000                ; physical, even
W       equ     360                     ; bytes per line at 8 bpp

        ld      hl,l0regs
        ld      d,(l0end-l0regs)/3
.next:  ld      b,(hl)                  ; register (port high byte)
        inc     hl
        ld      c,(hl)                  ; page (port low byte)
        inc     hl
        ld      a,(hl)
        inc     hl
        out     (c),a
        dec     d
        jr      nz,.next
        ld      bc,DMACON_P
        ld      a,DMACON_SETCLR_M|DMACON_DMAEN_M|DMACON_BPLEN_M
        out     (c),a
        ret

    MACRO PR port, val
        db      high (port), low (port), (val) & 0xFF
    ENDM
l0regs: PR      L0_CTRL0_P, L_CTRL0_EN_M|(3<<L_CTRL0_BPP_B)|(1<<L_CTRL0_HSCALE_B)
        PR      L0_CTRL1_P, 1<<L_CTRL1_VSCALE_B     ; 2x down, PALOFS 0
        PR      L0_CTRL2_P, 0
        PR      L0_CTRL3_P, 0
        PR      L0_WINX0_P, VID_X0+VID_W            ; XEND 864
        PR      L0_WINX1_P, (VID_X0+VID_W)>>8
        PR      L0_WINX2_P, VID_X0                  ; XSTART 144
        PR      L0_WINX3_P, 0
        PR      L0_WINY0_P, VID_Y0+VID_H            ; YEND 625
        PR      L0_WINY1_P, (VID_Y0+VID_H)>>8
        PR      L0_WINY2_P, VID_Y0                  ; YSTART 49
        PR      L0_WINY3_P, 0
        PR      L0_SCROLLX0_P, 0
        PR      L0_SCROLLX1_P, 0
        PR      L0_BPLSTRIDE0_P, W
        PR      L0_BPLSTRIDE1_P, W>>8
        PR      L0_BPL0PT0_P, SCREEN                ; rewrite every frame
        PR      L0_BPL0PT1_P, SCREEN>>8
        PR      L0_BPL0PT2_P, SCREEN>>16
l0end:
```

Every frame (in the vertical blank) put BPL0PT back:

```asm
SCREEN  equ     0x020000
        ld      bc,L0_BPL0PT0_P
        ld      a,low SCREEN
        out     (c),a
        inc     b                       ; next register: byte 1
        ld      a,high SCREEN
        out     (c),a
        inc     b
        ld      a,SCREEN>>16
        out     (c),a
```

Write 16 palette entries (blue, green, red each) to PALETTE0 from entry 0 through the ports:

```asm
        ld      bc,PALIDX0_P
        xor     a
        out     (c),a                   ; entry 0
        inc     b
        out     (c),a                   ; palette 0 (PALIDX1); resets the byte counter
        ld      bc,PALDAT_P
        ld      hl,pal
        ld      d,16*3
.loop:  ld      a,(hl)
        out     (c),a                   ; B stays PALDAT; red steps the index
        inc     hl
        dec     d
        jr      nz,.loop
        ret
pal:    ds      16*3, 0                 ; blue, green, red per entry
```

The same through the register page, with window 7 mapped to page `0x3F8` (stack moved below `0xE000` first):

```asm
REGS    equ     0xE000
        ld      sp,0xE000
        ld      hl,0x3F8
        ld      bc,MMU7_0_P
        out     (c),l
        inc     b
        out     (c),h                   ; window 7 = the register page
        ld      hl,pal
        ld      de,REGS+REGS_PALETTE+3*16   ; PALETTE0 entry 16
        ld      bc,16*3
        ldir                            ; rising addresses: red last in each entry
        ret
pal:    ds      16*3, 0
```

Read the beam line (capture on the first byte):

```asm
        ld      bc,BEAMPOS0_P
        in      e,(c)                   ; HPIXEL low: captures all four bytes
        inc     b
        in      d,(c)                   ; HPIXEL high
        inc     b
        in      l,(c)                   ; VLINE low
        inc     b
        in      h,(c)                   ; VLINE high: HL = beam line
```

## Pitfalls and limits

- **KS2: L0 only.** L1/L2 registers read `0xFF`; use sprites for extra planes. No direct colour, no attribute layer.
- Pointers (BPL0PT, MAPPT, PATPT) are **physical** 22-bit SRAM addresses, not Z80 addresses. In the program map a Z80 address `0x2000`–`0xFFFF` equals its physical address; anything else, work it out from the MMU page (page × `0x2000` + offset). On the 2 MB KS2, bit 21 is ignored.
- BPL0PT is not reset at frame start: rewrite it every frame, or the picture rolls through memory.
- Writing a live pointer while the layer fetches can mix bytes with the fetcher's moves: write in the vertical blank (or, for a split, all three bytes between the layer's last fetch on line L and pixel 0 of L + 1, a copper job).
- There is no BPLxDAT, no planar mode, no BPLDMA: the layers' data registers are not visible.
- A colour changes only on its red byte; through the register page write blue, green, red in that order (`LDIR`, not `LDDR`).
- `PALDAT` is a stream port: do not `OTIR` it; `INC (HL)`-style read-modify-write on it moves the index.
- Port `0xFE`'s border write overrides BGCOLOR at once (all three bytes) and is a Spectrum colour (`0xD7` levels).
- HSTART-style limits apply to sprites, not layers: a layer window starting in the blank is clamped to the picture's edge.
- Over-budget screens show transparent groups (OVERRUN); enable VIDINTEN.OVERRUNn while developing to catch them.
- VBLANK is level-sensitive: an interrupt handler must clear VIDSTAT.VBLANK (write 1) or it re-enters at once.
