# Sprites

> retro-z80 reference for AI models writing Z80 code. Register tables between `<!-- gen:NAME -->` markers are generated from `fpga/regmap.def` by `python3 tools/llm_docs.py sprites`: never edit them by hand. Every ```asm block assembles on its own (`python3 tools/llm_docs.py --asm sprites`); general rules are in [system.md](system.md).

**Built on the KS2:** sprites 0 and 1 only (`NSPRITES = 2`); sprites 2–7's registers read `0xFF` and ignore writes. SPRDMA, SPRCOLL and SPRPALETTE are built. The sprite sequencer is **not built** on any board yet (`0x300`–`0x30F` read `0xFF`). The KS3 build is to have all eight.

## What it does

Eight hardware sprites of any size, 2/4/8 bits per pixel (value 0 transparent), each with a window in beam coordinates, fractional scaling across and down (5.11 steps), a DEPTH among the layers, and per-pixel collision flags. Images stream from SRAM through a 32-word FIFO per sprite, just in time; sprites never slow the CPU. Colours come from SPRPALETTE (palette 3), or PALETTE0 with VIDCON.SHAREPAL.

## Enable

| What | Needs |
|------|-------|
| Sprite n fetches | SPRDMA bit n (all on after reset), DMACON.SPREN, DMACON.DMAEN |
| Sprite n shows | A write to **SPRnCTL** this frame (it starts the sprite), with a non-empty window |

**The vertical blank (beam line 0, pixel 0) stops every sprite.** Nothing restarts by itself: every frame, write each sprite's PT (and H, V, STEP as needed) then **CTL last**, from the VBLANK handler or (better) from the copper list.

Names: `SPR0_X` … `SPR7_X` (offset), `_P` (port); `SPR_X` is the offset inside an element (add to `SPRn`).

| Field | Meaning |
|-------|---------|
| PT | Physical address of the image's first line, even (bit 0 ignored). Moves line by line as the sprite is drawn; reading byte 0 captures all three bytes |
| H: HSTART (bytes 0–1), HSTOP (bytes 2–3) | Beam pixels: `HSTART ≤ x < HSTOP`. **HSTART ≥ 16** (the fetch needs a lead); pixels before 144 are fetched but not shown (left clipping); HSTOP above 864 counts as 864 |
| V: VSTART (bytes 0–1), VSTOP (bytes 2–3) | Beam lines: `VSTART ≤ y < VSTOP`; lines before 49 fetched but not shown; VSTART ≥ 625 hides the sprite. Empty window (stop ≤ start): nothing shows. Reset: empty |
| CTL.BPP | 0 = 2, 1 = 4, 2 = 8 bits per pixel (3 = 8) |
| CTL.DEPTH | 0 in front of all layers; 1 behind PRIO.FRONT; 2 behind PRIO.MIDDLE; 3 behind PRIO.BACK |
| CTL.PAL | 2 and 4 bpp: colour = PAL × 16 + value. Unused at 8 bpp |
| STEP: XSTEP (bytes 0–1), YSTEP (bytes 2–3) | Source pixels (lines) per screen pixel (line), 5.11 fixed point: `0x0800` normal, `0x0400` 2× bigger, `0x1000` half, `0x0080`–`0x8000` (16× to 1/16). **0 counts as `0x0800`** (reset value) |

- **SPRDMA** is a 2-byte set/clear: write the sprite bits to SPRDMA0, then write SPRDMA1 with bit 7 (SETCLR) 1 to set or 0 to clear them; the SPRDMA1 write is the trigger. `SPRDMA_SETCLR_M` is `0x8000` (bit 15 of the 2-byte value): write `SPRDMA_SETCLR_M >> 8` to SPRDMA1. Reading SPRDMA0 gives the enables. Reset `0xFF`. Turning DMA off pauses fetching (no SPRUNDER); it does not stop a sprite.
- **SPRCOLL0** bit n: sprite n touched another sprite. **SPRCOLL1/2/3** bit n: sprite n touched layer L0/L1/L2. Opaque pixels only, picture pixels only, regardless of DEPTH. Sticky W1C; all of a frame's collisions are in by the next vertical blank. No collision interrupt.
- **VIDSTAT.SPRUNDER** (W1C): a sprite's FIFO ran dry; that sprite shows nothing more until its CTL is written. With VIDINTEN.SPRUNDER it raises VIDERR (source 3).

## Data structures

**Image:** lines one after another, top first. Each line is ⌈source width × bits ÷ 16⌉ **words** (whole 16-bit words, so an even number of bytes), chunky, leftmost pixel in the highest bits of each byte, bytes left to right. Source width = ⌈(HSTOP − HSTART) × XSTEP ÷ 2048⌉, source height = ⌈(VSTOP − VSTART) × YSTEP ÷ 2048⌉; at normal size the image is the window's size. Value 0 is transparent.

| BPP | Bits | Pixels a byte | Bytes a line, 16 pixels wide |
|-----|------|---------------|------------------------------|
| 0 | 2 | 4 | 4 |
| 1 | 4 | 2 | 8 |
| 2 | 8 | 1 | 16 |

**Register block** (also the sequencer's 16-byte list entry): `+0` PT (3), `+3` H (4: HSTART, HSTOP), `+7` V (4: VSTART, VSTOP), `+11` CTL (1), `+12` STEP (4: XSTEP, YSTEP), each value low byte first.

**SPRnCTL**, one byte:

| Bits 7–4 | Bits 3–2 | Bits 1–0 |
|----------|----------|----------|
| PAL | DEPTH | BPP |

**Order:** DEPTH first (see [video-layers.md](video-layers.md) for the full stack), then lower sprite number in front. PRI tile pixels cover DEPTH 1–3 sprites, never DEPTH 0.

## When writes take effect

| Register | Effect |
|----------|--------|
| SPRnCTL | On the write: starts the sprite (FIFO emptied); its first line is the next beam line inside its window, from SPRnPT |
| SPRnPT, H, V, STEP | Running sprite: from the next line that starts after the write. Stopped sprite: when started |
| Vertical blank | Stops every sprite |
| SPRDMA, DMACON.SPREN | At once; pauses or resumes fetching only |

Write a running sprite's PT all three bytes within one line. To reuse a sprite lower down (copper), after its last line E: `CWAIT E+1,0`, then PT, H, V, STEP, CTL; the new use can start on line E + 2.

## Memory budget

The display's cycles give about 12 words per 16 screen pixels for sure, shared with the layers. A sprite needs BPP words per 16 source pixels while the beam is over it (× XSTEP ÷ 2048 per 16 screen pixels). Sprites side by side do not add up; stacked ones do. With no layer: 1 stacked 8 bpp, 3 at 4 bpp, 6 at 2 bpp guaranteed (more from spare cycles). Bigger down re-fetches each line. Over budget → SPRUNDER.

## Recipes

Show sprite 0 for one frame from the CPU (in the vertical blank): a 16 × 16 sprite at 4 bpp, PAL 1, in front of all layers, at picture (100, 50). PT, H, V and CTL are consecutive registers, so `INC B` walks them; STEP stays 0 (normal size).

```asm
X0      equ     VID_X0+100
Y0      equ     VID_Y0+50

        ld      bc,SPR0_PT0_P
        ld      hl,ship                 ; program map: Z80 address = physical
        out     (c),l
        inc     b
        out     (c),h
        inc     b
        xor     a
        out     (c),a                   ; PT bits 21-16
        inc     b
        ld      hl,X0
        ld      de,X0+16
        out     (c),l                   ; HSTART
        inc     b
        out     (c),h
        inc     b
        out     (c),e                   ; HSTOP
        inc     b
        out     (c),d
        inc     b
        ld      hl,Y0
        ld      de,Y0+16
        out     (c),l                   ; VSTART
        inc     b
        out     (c),h
        inc     b
        out     (c),e                   ; VSTOP
        inc     b
        out     (c),d
        inc     b                       ; SPR0_CTL: last, starts the sprite
        ld      a,(1<<SPR_CTL_PAL_B)|(0<<SPR_CTL_DEPTH_B)|(1<<SPR_CTL_BPP_B)
        out     (c),a
        ld      bc,DMACON_P
        ld      a,DMACON_SETCLR_M|DMACON_DMAEN_M|DMACON_SPREN_M
        out     (c),a
        ret

        ALIGN   2
ship:   ds      16*8, 0x11              ; 16 lines of 8 bytes: colour 1 (PAL 1: SPRPALETTE entry 17)
```

The same sprite every frame from the copper (the usual way): the list restarts at each frame and rewrites the registers, CTL last. Start the copper as in [copper.md](copper.md) with DMACON.SPREN set too.

```asm
        device  zxspectrum48
        org     0x8000
        include "hw.inc"
        include "copper.inc"
X0      equ     VID_X0+100
Y0      equ     VID_Y0+50

        ALIGN   2
list:   CMOVEA  SPR0_PT,ship
        CMOVEL  SPR0_H,((X0+16)<<16)|X0         ; HSTART low half, HSTOP high half
        CMOVEL  SPR0_V,((Y0+16)<<16)|Y0
        CMOVEL  SPR0_STEP,0x08000800            ; normal size both ways
        CMOVE   SPR0_CTL,(1<<SPR_CTL_PAL_B)|(1<<SPR_CTL_BPP_B)  ; starts it
        CSTOP

        ALIGN   2
ship:   ds      16*8, 0x11
```

Move it from the CPU by changing the copper list's data bytes (each `CMOVE` word's low byte is its value), or by having the CPU write H/V in the VBLANK handler and the list only PT and CTL.

Twice the size across, normal down:

```asm
        ld      bc,SPR0_STEP0_P
        xor     a
        out     (c),a                   ; XSTEP 0x0400: 2x bigger across
        inc     b
        ld      a,0x04
        out     (c),a
        inc     b
        xor     a
        out     (c),a                   ; YSTEP 0x0800: normal
        inc     b
        ld      a,0x08
        out     (c),a
```

Sprite DMA off for sprite 1 only, then read and clear collisions:

```asm
        ld      bc,SPRDMA0_P
        ld      a,0x02                  ; sprite 1
        out     (c),a
        inc     b                       ; SPRDMA1: the trigger
        xor     a                       ; SETCLR 0: clear
        out     (c),a

        ld      bc,SPRCOLL0_P
        in      a,(c)                   ; sprite-sprite bits
        out     (c),a                   ; W1C: clear what was seen
```

Set SPRPALETTE entry 17 (PAL 1, value 1) through PALIDX/PALDAT:

```asm
        ld      bc,PALIDX0_P
        ld      a,17
        out     (c),a
        inc     b
        ld      a,3                     ; palette 3 = SPRPALETTE
        out     (c),a
        ld      bc,PALDAT_P
        ld      a,0x00
        out     (c),a                   ; blue
        ld      a,0xFF
        out     (c),a                   ; green
        out     (c),a                   ; red: commits
```

## Pitfalls and limits

- **KS2: two sprites.** Writes to sprites 2–7 do nothing there; reads give `0xFF`.
- Not writing CTL in a frame = no sprite that frame. The vertical blank kills every sprite.
- Write PT, H, V, STEP first and CTL last; a CTL write restarts the sprite (FIFO emptied).
- PT is a **physical** address and must be even; image lines are whole words.
- HSTART must be at least 16. A sprite cannot show on beam line 0.
- SPRDMA1 is a trigger: write SPRDMA0 first. Never read-modify-write SPRDMA.
- No flip: store mirrored images if needed.
- `SPRDMA_SETCLR_M` is a 16-bit mask; use `>> 8` for the byte.
- Stacked wide 8 bpp sprites over busy layers underrun (SPRUNDER); use fewer bits, scale up a narrower image, or spread them out.
- Collision bits do not say which other sprite was hit.
- Let one master (CPU or copper) own each sprite's registers.
