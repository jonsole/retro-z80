# Geometry unit

> retro-z80 reference for AI models writing Z80 code. Register tables between `<!-- gen:NAME -->` markers are generated from `fpga/regmap.def` by `python3 tools/llm_docs.py geometry`: never edit them by hand. Every ```asm block assembles on its own (`python3 tools/llm_docs.py --asm geometry`); general rules are in [system.md](system.md).

**Built on the KS2: NOT in the default bitstream.** Only `fpga/ks2/build.sh --geom` (`GEOM = 1`, into `fpga/ks2/build/geom/`) builds it, and that build leaves out the blitter and the rasteriser. In the default build (`GEOM = 0`) registers `0xA0`–`0xBF` read `0xFF` and ignore writes. Ask the user which bitstream is loaded before relying on it; test with the probe below. The KS3 is to build all three.

## What it does

A 3D maths coprocessor in the system page: two 3×3 matrices with positions (camera, object), kept multiplied together by the hardware; a vertex job (turn, translate, optional perspective projection with a near-plane test), a face-sign (back-face) job, a 16×16→32 signed multiply and a 32÷16 signed divide. Each job is done within 24 clocks (0.24 µs) of its start write: the CPU can never read a result too early. No memory cycles, no interrupt.

## Enable

Nothing to enable: load the view and matrices, set GEOCTL, write operands. Writing the **high byte of a job's last operand starts it**:

| Job | Bank (GEOCTL.BANK) | Start byte |
|-----|--------------------|------------|
| Vertex | any | `GEOVZ1` (register `0xBD`) |
| Face sign | 3, operands | F2Y high byte (`GEO_F2Y+1`) |
| Multiply | 3 | MB high byte (`GEO_MB+1`) |
| Divide | 3 | DVS high byte (`GEO_DVS+1`) |

Probe (default build reads `0xFF`; GEOCTL bits 7–6 read 0 when built):

```asm
        ld      bc,GEOCTL_P
        in      a,(c)
        cp      0xFF
        jr      z,no_geom               ; not built in this bitstream
        ret
no_geom:
        ret
```

- `0xA0`–`0xB7` (GEOW0–11) are a window of twelve 16-bit words onto the bank in GEOCTL.BANK (table below).
- `0xB8`–`0xBD`: write = the vertex x, y, z (GEOVX, GEOVY, GEOVZ); read = the results RX, RY, RZ (not the values written).
- GEOCTL: BANK (2–0), PROJ (3) project vertices, CAM (4) the camera alone, INV (5) the inverse turn. Reset 0.
- GEOSTAT: BUSY (0, live; never seen set by the CPU), NEAR (1), SAT (2), DIVZ (3), FRONT (4) belong to the last job; SATS (7) sticky, W1C.
- Reset: everything 0 (matrices 0: every vertex gives 0, 0, 0).

## Data structures

**Numbers:**

| Kind | Format |
|------|--------|
| Coordinates, positions, results | Signed 16-bit integers. Positions wrap: P − C and v − C are taken modulo 65,536 |
| Matrix entries | Signed 2.14: `0x4000` = 1.0, `0xC000` = −1.0, `0x7FFF` = 1.99994 |
| Turned results | 48-bit inside, rounded to nearest (halves up) after each row, saturated to ±32767 (sets SAT, SATS) |
| Perspective divide | Rounds down (towards −∞) |
| Plain divide | Rounds towards zero; remainder takes the dividend's sign |

**Vertex job** (GEOCTL.CAM, INV):

| CAM | INV | Result (RX, RY, RZ) | Use |
|-----|-----|---------------------|-----|
| 0 | 0 | M·v + T = Mc·(Mo·v + P − C) | Object vertex in camera space |
| 1 | 0 | Mc·(v − C) | World point in camera space (cull by centre) |
| 0 | 1 | Mᵀ·(v − T) | Eye into model space |
| 1 | 1 | Mcᵀ·v + C | Camera space back to world |

M = Mc·Mo and T = Mc·(P − C) are recomputed by the hardware after any byte of the camera or object bank is written (24 clocks; a job waits for it). Camera space: x right, y up, z into the screen. Mc = transpose of the camera's own rotation.

**Projection** (PROJ = 1): if Z < ZMIN (ZMIN below 1 counts as 1): NEAR set, results stay X, Y, Z. Else RX = SCX + ⌊DX·X ÷ Z⌋, RY = SCY − ⌊DY·Y ÷ Z⌋ (screen y down), RZ = Z.

**Face sign:** s = (F1X − F0X)(F2Y − F0Y) − (F1Y − F0Y)(F2X − F0X); RX = s bits 15–0, RY = bits 31–16; FRONT = s ≥ 0 (anticlockwise seen from outside, y down, faces the eye).
**Multiply:** RX:RY = MA × MB (32-bit, low word in RX). **Divide:** RX = DVD ÷ DVS (saturated), RY = remainder; DVS = 0 sets DIVZ, RX = ±32767/−32768.

## Recipes

Project one vertex (adapted from Example 9-1, run on the KS2 `--geom` build). The register page goes into window 7 so the window is ordinary memory; `LDI` writes rising, so GEOVZ1 goes last and starts the job:

```asm
PG_REGS equ     0x3F8
SREG    equ     0xE000                  ; the register page in window 7
GEO     equ     SREG + GEOW0            ; the window of 12 words
GEO_V   equ     SREG + GEOVX            ; VX0, or RX0 when read
GEO_CTL equ     SREG + GEOCTL
GEO_ST  equ     SREG + GEOSTAT
EXIT    equ     0x0040

start:  ld      sp,0xC000               ; stack out of window 7
        ld      hl,PG_REGS
        ld      bc,MMU7_0_P
        out     (c),l
        inc     b
        out     (c),h                   ; window 7 = the registers

        ld      a,GEO_BANK_VIEW
        ld      (GEO_CTL),a
        ld      hl,view
        ld      de,GEO
        ld      bc,10
        ldir                            ; DX, DY, SCX, SCY, ZMIN
        ld      a,GEO_BANK_CAM
        ld      (GEO_CTL),a
        ld      hl,identity
        ld      de,GEO
        ld      bc,24
        ldir                            ; Mc, then C
        ld      a,GEO_BANK_OBJ
        ld      (GEO_CTL),a
        ld      hl,object
        ld      de,GEO
        ld      bc,24
        ldir                            ; Mo, then P: M and T follow by themselves

        ld      a,GEO_BANK_OBJ|GEOCTL_PROJ_M
        ld      (GEO_CTL),a
        ld      hl,vertex
        ld      de,GEO_V
        ldi                             ; x, y, z low byte first: VZ1 last starts it
        ldi
        ldi
        ldi
        ldi
        ldi
        ld      a,(GEO_ST)              ; done already
        and     GEOSTAT_NEAR_M
        jr      nz,.near                ; results are X, Y, Z unprojected
        ld      hl,(GEO_V)              ; RX = screen x
        ld      (sx),hl
        ld      hl,(GEO_V+2)            ; RY = screen y
        ld      (sy),hl
.near:  ld      hl,7
        ld      (SREG+MMU7),hl          ; window 7 back to SRAM page 7
        jp      EXIT

view:   dw      256, 256, 128, 96, 16   ; DX, DY, SCX, SCY, ZMIN
identity:
        dw      0x4000, 0, 0, 0, 0x4000, 0, 0, 0, 0x4000
        dw      0, 0, 0                 ; C: the origin
object: dw      0x4000, 0, 0, 0, 0x4000, 0, 0, 0, 0x4000
        dw      0, 0, 512               ; P: 512 ahead
vertex: dw      -100, 50, 0             ; -> (78, 71), z 512
sx:     dw      0
sy:     dw      0
```

Multiply and divide (register page in window 7 as above; bank 3):

```asm
SREG    equ     0xE000
        ld      a,GEO_BANK_OPS
        ld      (SREG+GEOCTL),a
        ld      hl,1234
        ld      (SREG+GEO_MA),hl
        ld      hl,-567
        ld      (SREG+GEO_MB),hl        ; LD (nn),HL writes L then H: H starts it
        ld      hl,(SREG+GEOVX)         ; RX: product bits 15-0
        ld      de,(SREG+GEOVY)         ; RY: bits 31-16
        ld      hl,0
        ld      (SREG+GEO_DVD),hl       ; dividend bits 15-0
        ld      hl,1
        ld      (SREG+GEO_DVDHI),hl     ; bits 31-16: 65,536
        ld      hl,3
        ld      (SREG+GEO_DVS),hl       ; starts the divide
        ld      hl,(SREG+GEOVX)         ; quotient 21845
        ld      de,(SREG+GEOVY)         ; remainder 1
```

Matrix product A·B: load A into the camera bank, B into the object bank, then read 18 bytes of bank 4 (M11–M33) with `LDIR` (wait one instruction after the last write).

Speed (KS2): spec 15's `LDI`-in/`LD rr,(nn)`-out loop is 316 T-states a vertex (1,024 in 16,160 µs); a `POP`/`LD (nn),HL`/`PUSH` loop with interrupts off 172 T (`examples/geometry/geomtest.asm`). The Z80's byte moves are the limit, not the unit.

## Pitfalls and limits

- Not in the default KS2 bitstream; with it, there is no blitter or rasteriser (draw lines in software, e.g. `examples/geometry/screen.inc`).
- **Write the start byte last**: rising writes only (`LD (nn),HL`, `LDI`/`LDIR`, `OUT (C),r` + `INC B`). `PUSH`, `LDDR` and unrolled `OUTI` write the high byte first and start the job too early.
- The result registers share addresses with the vertex inputs: reading VX0 gives RX, not x.
- GEOCTL selects the bank **and** the job mode in one byte: writing BANK also rewrites PROJ/CAM/INV.
- Results and NEAR/SAT/DIVZ/FRONT are replaced by the next job; read them before starting another.
- Matrix entries range −2.0 to +1.99994; scaling by more than 2 saturates. A world wider than ±32,767 from the camera wraps.
- Interrupt 19 (GEOM) is reserved; the unit raises no interrupt.
- Registers are in the system page: the copper, blitter and rasteriser cannot reach them.
