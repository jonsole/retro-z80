# Copper

> retro-z80 reference for AI models writing Z80 code. Register tables between `<!-- gen:NAME -->` markers are generated from `fpga/regmap.def` by `python3 tools/llm_docs.py copper`: never edit them by hand. Every ```asm block assembles on its own (`python3 tools/llm_docs.py --asm copper`); general rules are in [system.md](system.md).

**Built on the KS2:** yes, in the default build. Not in the `build.sh --no-copper` build: there its registers read `0xFF` and it never runs or interrupts.

## What it does

A display co-processor: a list of 16-bit instruction words in SRAM, restarted from COP1LC at every frame start (beam line 0, pixel 0), that waits for beam positions and writes custom registers with pixel accuracy. It has X, Y, flags, eight storage registers COPR0–7, an ALU, conditional skips and an 8-deep call stack. It only writes registers; it never writes SRAM and never reads registers.

## Enable

All three: **COPCON.EN**, **DMACON.COPEN** and **DMACON.DMAEN**. Then it starts from COP1LC at the next frame restart, or at once on a write to COPJMP1. Clearing any one stops it at once.

## Data structures: instruction words

Words are little-endian at **even** addresses (`ALIGN 2`; `dw`). The high byte of word 1 is the code. Bits shown 0 must be 0. Use the `copper.inc` macros (`include "copper.inc"` after `hw.inc`); register arguments are custom offsets (`BGCOLOR`, `L0_SCROLLY0`), not ports.

| Instruction | Word 1 bits 15–8 | Word 1 bits 7–0 | Word 2 | Macro |
|-------------|------------------|-----------------|--------|-------|
| MOVE | offset `0x00`–`0xEF` | data | – | `CMOVE reg,val` |
| WAIT | `0xF0` | 7 P, 6 B, 5–4 0, 3–2 line 9–8, 1–0 pixel 9–8 | 15–8 line 7–0, 7–0 pixel 7–0 | `CWAIT l,p` `CWAITP p` `CWAITB l,p` |
| SKIP | `0xF1` | 7 P, 6–4 0, 3–2 line 9–8, 1–0 pixel 9–8 | as WAIT | `CSKIP l,p` `CSKIPP p` |
| JUMP | `0xF2` | 7–6 0, 5–0 address 21–16 | address 15–0 (bit 0 = 0) | `CJUMP addr` |
| STOP | `0xF3` | 0 | – | `CSTOP` |
| MOVR (X) ← value | `0xF4` | value | – | `CMOVX v` |
| MOVR (X) ← value, X+1 | `0xF5` | value | – | `CMOVXP v` |
| MOVR reg ← X | `0xF6` | register code `0x00`–`0xFF` | – | `CMOVR reg,CX` |
| MOVR reg ← Y | `0xF7` | register code | – | `CMOVR reg,CY` |
| MOVR (X) ← Y or X | `0xF8` | 7–2 0, 1 I (X+1 after), 0 R (1: X, 0: Y) | – | `CMOVXR src` `CMOVXRP src` |
| ALU | `0xF9` | 7–5 fn, 4 d (0 X, 1 Y), 3–0 source | only if source = 10: 15–8 0, 7–0 value | see below |
| SKIPC | `0xFA` | 7–4 0, 3–0 cc | – | `CSKIPEQ` … `CSKIPLS` |
| CALL | `0xFB` | 7 R = 0, 6 0, 5–0 address 21–16 | address 15–0 (bit 0 = 0) | `CCALL addr` |
| RET | `0xFB` | 7 R = 1, rest 0 (`0x80`) | – | `CRET` |
| MOVEF | `0xFC` | 7–2 0, 1–0 offset 9–8 | 15–8 offset 7–0, 7–0 data | `CMOVEF reg,val` |
| reserved | `0xFD`–`0xFF` | | | stops the copper, sets COPSTAT.ERR |

Wider writes: `CMOVEB reg,val` (MOVE or MOVEF as the offset needs), `CMOVEW`/`CMOVEA`/`CMOVEL reg,val` (2/3/4 bytes, low byte first, one MOVE or MOVEF per byte), `CMOVEN reg,val,n`.

**ALU** source: 0–7 COPR0–7 (`CR0`–`CR7`), 8 X (`CX`), 9 Y (`CY`), 10 the value in word 2, 11–15 reserved.

| fn | Op | Result | Flags | Macros |
|----|----|--------|-------|--------|
| 0 | LD | d = source | unchanged | `CLD d,src` `CLDI d,v` |
| 1 | ST | Rn = d (source must be Rn) | unchanged | `CST CRn,d` |
| 2 | ADD | d += source | Z, N, C carry | `CADD` `CADDI` |
| 3 | SUB | d −= source | Z, N, C borrow | `CSUB` `CSUBI` |
| 4 | AND | d &= source | Z, N; C = 0 | `CAND` `CANDI` |
| 5 | OR | d \|= source | Z, N; C = 0 | `COR` `CORI` |
| 6 | CMP | d − source, not kept | as SUB | `CCMP` `CCMPI` |
| 7 | flags | d = 0: flags = source bits 2–0; d = 1: Rn = flags | | `CLD CF,src` `CLDI CF,v` `CST CRn,CF` |

Flags: Z (bit 0), N (bit 1, result bit 7), C (bit 2). 8-bit, wrapping.

**SKIPC** cc: 0 EQ (Z), 1 NE, 2 LO (C), 3 HS (not C), 4 MI (N), 5 PL, 6 HI (not C and not Z), 7 LS (C or Z); 8–15 reserved. Skips the next instruction (all its words) if the condition holds.

**WAIT/SKIP semantics.** Positions are beam coordinates (picture: pixels 144–863, lines 49–624; `VID_X0` = 144, `VID_Y0` = 49). WAIT ends when the beam has reached (line, pixel); a passed position ends it at once; line ≥ 625 or pixel ≥ 864 waits until the next frame (so `CWAIT 1023,0` ends a list). P = 1: pixel only, the next time the beam reaches that pixel (current line or next). B = 1 (`CWAITB`): also wait until the blitter and the rasteriser are both idle; `CWAITB 0,0` waits for them only. SKIP skips the next instruction if the beam has reached the position (B is reserved in SKIP). `CWAIT L,0` ends at the start of line L's horizontal blank, 144 pixels before its picture.

## Timing

- Fetch: one word per memory cycle from cycle 4 and the free pool. At **PRI 1** on a screen within the display budget: one word every 100 ns slot (2.7 pixels), so 320 one-word MOVEs per line, 53 in the horizontal blank, 15,680 in the vertical blank. PRI 0 is best effort (default; fine for lists that mostly wait).
- Cost in words: MOVE, MOVR, ALU with register, SKIPC, STOP, RET = 1; WAIT, SKIP, JUMP, CALL, MOVEF, ALU with value = 2. Skipped instructions still cost their words. Loops cost every word every pass.
- Prefetch: two words. The first MOVE after a WAIT lands within a pixel of the position; the second 20 ns later; later ones a fetch apart.
- The copper wins the register bus over the CPU: its writes are never delayed.
- Write timing is the target's (see [video-layers.md](video-layers.md), [sprites.md](sprites.md)): line settings (CTRL, window, SCROLLX/Y, MAPPT) at beam pixel 0, so to change line L write during line L − 1; PRIO and BGCOLOR at pixel 144, so a write in line L's horizontal blank still changes line L; palette entries at once.

## Recipes

Start a list (Example 5-2's set-up). In the program map the list's Z80 address is its physical address.

```asm
        device  zxspectrum48
        org     0x8000
        include "hw.inc"
        include "copper.inc"

start:  ld      bc,COPCON_P             ; off while it is set up
        xor     a
        out     (c),a
        ld      hl,list
        ld      bc,COP1LC0_P
        out     (c),l
        inc     b
        out     (c),h
        inc     b
        out     (c),a                   ; bits 21-16: 0
        ld      bc,COPCON_P
        ld      a,COPCON_EN_M
        out     (c),a
        ld      bc,DMACON_P
        ld      a,DMACON_SETCLR_M|DMACON_DMAEN_M|DMACON_COPEN_M
        out     (c),a                   ; starts at the next frame restart
        ret

        ALIGN   2
list:   CMOVEA  BGCOLOR,0x0000FF        ; vertical blank: blue (0xRRGGBB, red byte last)
        CWAIT   VID_Y0+288,0            ; mid-picture, in the line's horizontal blank
        CMOVEA  BGCOLOR,0xFF0000        ; red from here
        CSTOP
```

Colour bars: a DUP-generated list (from `examples/copper/bars.asm`).

```asm
        device  zxspectrum48
        org     0x8000
        include "hw.inc"
        include "copper.inc"
BAR     equ     16
        ALIGN   2
bars:   CMOVEA  BGCOLOR,0x0000FF
b = 1
        DUP     35
        CWAIT   VID_Y0+b*BAR,0
        CMOVEA  BGCOLOR,((b*7)<<16)|(255-b*7)
b = b + 1
        EDUP
        CSTOP
```

A colour change exactly at a pixel: blue and green before the WAIT (they wait in the copper's colour buffer), red after.

```asm
        device  zxspectrum48
        org     0x8000
        include "hw.inc"
        include "copper.inc"
        ALIGN   2
        CMOVE   BGCOLOR0,0x00           ; blue
        CMOVE   BGCOLOR1,0xFF           ; green
        CWAIT   300,VID_X0+360          ; line 300, mid-screen
        CMOVE   BGCOLOR2,0x00           ; red: the colour changes here
        CSTOP
```

Split screen: from line 300 the tile layer shows map line 0 again (SCROLLY is read at pixel 0, so write it in the line before).

```asm
        device  zxspectrum48
        org     0x8000
        include "hw.inc"
        include "copper.inc"
        ALIGN   2
        CMOVEW  L0_SCROLLY0,40          ; top part scrolled 40 lines
        CWAIT   299,VID_X0+720-1        ; late in line 299
        CMOVEW  L0_SCROLLY0,0           ; line 300 on: unscrolled
        CSTOP
```

A per-line loop to line 400 with SKIP, and a counted loop with the ALU:

```asm
        device  zxspectrum48
        org     0x8000
        include "hw.inc"
        include "copper.inc"
        ALIGN   2
        CWAIT   100,0
loop:   CWAITP  0                       ; start of each line's horizontal blank
        CMOVE   PRIO,0x24
        CSKIP   400,0
        CJUMP   loop
        CLDI    CY,8                    ; 8 passes
count:  CWAITP  0
        CMOVEA  BGCOLOR,0x202020
        CSUBI   CY,1
        CSKIPEQ
        CJUMP   count
        CMOVEF  COPINT,0                ; raise interrupt source 2 (with COPCON.IRQEN)
        CSTOP
```

Double-buffered lists: build next frame's list in the other buffer, then point COP1LC at it from the VBLANK handler (well away from the frame restart; COP1LC's bytes are not latched).

```asm
; HL = the new list's physical address (bits 21-16 = 0 here)
        ld      bc,COP1LC0_P
        out     (c),l
        inc     b
        out     (c),h
        inc     b
        xor     a
        out     (c),a
```

Change a palette entry from the copper (the copper has its own PALIDX): 5 MOVEs.

```asm
        device  zxspectrum48
        org     0x8000
        include "hw.inc"
        include "copper.inc"
        ALIGN   2
        CMOVE   PALIDX0,5               ; entry 5
        CMOVE   PALIDX1,0               ; PALETTE0 (3 = SPRPALETTE)
        CMOVE   PALDAT,0x40             ; blue
        CMOVE   PALDAT,0x80             ; green
        CMOVE   PALDAT,0xFF             ; red: commits, index steps to 6
        CSTOP
```

## Pitfalls and limits

- **Reach:** MOVE writes offsets `0x000`–`0x0EF` only (video globals, sprites, layers); `CMOVE` with a larger offset is an assembly error. MOVR reaches `0x000`–`0x0FF`; MOVEF (2 words) reaches the whole custom block `0x000`–`0x3FF` (copper registers, SPRDMA/SPRCOLL, blitter, rasteriser, audio). Nothing in the system page: no MMU, interrupt controller, timers, port `0xFE`, register-page palettes.
- Lists must be at **even** physical addresses (`ALIGN 2`); JUMP/CALL targets even. Erased memory (`0xFFFF`) and the Amiga end `0xFFFF,0xFFFE` are reserved instructions: the copper stops with COPSTAT.ERR.
- COP1LC/COP2LC/JUMP addresses are **physical** (see [system.md](system.md)); bit 0 ignored.
- A list still running at the next frame restart is abandoned; it restarts from COP1LC.
- No latches: a wide register is mixed between its MOVEs. Write layer pointers while the layer is not fetching; sprite PT/H/V/STEP before CTL (CTL starts the sprite).
- Pixel-only WAITs (`CWAITP`) slip a line if the block before them overruns its pixel; start a run of them with an ordinary WAIT.
- The copper cannot read registers or SRAM: values come from the list, from the CPU (COPX, COPY, COPR0–7), or from ALU results.
- CALL with the stack full or RET with it empty stops the copper and sets ERR. The frame restart empties the stack unless STKKEEP.
- With RESUME, a background list (list 2) should use only `CWAITP`/`CWAITB 0,0`, write no colours, and never put a strobe between the bytes of a register; list 1 ends with `CMOVEF COPJMP2,0`.
- Let one master own each register: CPU and copper writes interleave byte by byte.
- `COP_B` in `copper.inc` and the WAIT B bit now wait for the blitter and the rasteriser (the file's comment still says "DMA engine").
