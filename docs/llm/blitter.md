# Blitter

> retro-z80 reference for AI models writing Z80 code. Register tables between `<!-- gen:NAME -->` markers are generated from `fpga/regmap.def` by `python3 tools/llm_docs.py blitter`: never edit them by hand. Every ```asm block assembles on its own (`python3 tools/llm_docs.py --asm blitter`); general rules are in [system.md](system.md).

**Built on the KS2:** yes, without the 1 bpp mask image (`DMX_MASKIMG 0`: BLTCTRL.MASK = 1 is an error). Not in the KS2's `--geom` build (`DMX 0`: registers read `0xFF`, always idle).

## What it does

Works on rectangles of pixels in SRAM: copy, fill, combine, cookie-cut. Each destination pixel D = MINTERM(A, B, C) bit by bit: A a mask, B a source (memory or the constant VALUE), C the destination's old pixel. One job at a time; a job can chain to the next descriptor. Uses only free memory cycles: the Z80 never waits.

This is the version-2 blitter (ticket #103). There are no channels, no ADD, LINE or EDGES jobs, no PAUSE, no timer starts: code for the old 4-channel "DMA engine" does not work. Lines and triangles are the [rasteriser](rasteriser.md).

## Enable

| Need | Write |
|------|-------|
| Memory cycles | DMACON.DMAEN and DMACON.BLTEN (one SC write: `DMACON_SETCLR_M \| DMACON_DMAEN_M \| DMACON_BLTEN_M`). Both clear after reset. BLTEN also enables the rasteriser |
| Interrupt (optional) | DMXINTEN.BLT, INTENA bit for source 4 (`INT_BLT`), INTCON.MASTER, IM 2 ([interrupts-timers.md](interrupts-timers.md)) |

While BLTEN or DMAEN is clear, a started job waits (BLTSTAT.BUSY stays 1) before its next memory access.

- Custom block, page `0x11`: every job register is port `(offset & 0xFF) << 8 | 0x11`, so `INC B` steps through all 32 job bytes with C = `0x11`. Register page: offset + `0x1000`.
- **Job registers** (`0x140`–`0x15F`): writes ignored while BUSY. Not reset (0 at power-on). Reserved bits are not stored and read 0 (no error). They hold the job as loaded, not its progress: after a job, rewrite only what changes and RUN.
- **BLTDESC**: 3 bytes; bit 0 and bits 23–22 not kept. Reading `BLTDESC0` captures all three bytes. Reset 0.
- **BLTCMD** (strobe, reads 0): START (bit 0) loads the descriptor at BLTDESC then runs; RUN (bit 1) runs the job registers as they are; START wins over RUN; both ignored while BUSY. STOP (bit 2) ends the job after the word in hand, does not follow BLTNEXT, sets DMXINT.BLT; ignored while idle.
- **BLTSTAT**: BUSY (bit 0) is set by the START/RUN write itself, so a read straight after already sees it. ERR (bit 2) cleared by the next START or RUN.
- **DMXINT/DMXINTEN** are shared with the rasteriser (bit 1, RAS). DMXINT.BLT is set at the end of a job with IRQ, and whenever the blitter stops (end of chain, STOP, error). W1C. A flag due in the same clock as its clearing write stays set (no lost interrupt). Interrupt source 4 (`INT_BLT`), IM 2 vector VECBASE + 8, requested while (BLT and its enable) or (RAS and its enable).

### BLTCTRL

| Bits | Byte | Field | Meaning |
|------|------|-------|---------|
| 31–24 | BLTCTRL3 | MINTERM | D bit = MINTERM bit number (4·A + 2·B + C) |
| 18–17 | BLTCTRL2 | MASK | A from: 0 none (A = 1), 1 the 1 bpp image at BLTAPT (**error on the KS2**), 2 B compared with KEY (A = 1 where B ≠ KEY), 3 error |
| 13 | BLTCTRL1 | BCONST | B = VALUE, not memory (a fill) |
| 12 | BLTCTRL1 | IRQ | Set DMXINT.BLT when this job ends |
| 10 | BLTCTRL1 | RTL | Work each row right to left; pointers name the row's last pixel |
| 9–8 | BLTCTRL1 | BPP | 0 = 1, 1 = 2, 2 = 4, 3 = 8 bits per pixel (A, B, C and D alike) |
| 7–0 | BLTCTRL0 | KEY | Key colour for MASK = 2, in its low BPP bits |

Pointer words (BLTBPT, BLTDPT, BLTAPT): ADDR 23–0 is the **physical** byte holding the first pixel; BIT 26–24 is that pixel's place in the byte counted in pixels from the most significant end (0–7 at 1 bpp, 0–3 at 2, 0–1 at 4, 0 at 8; for BLTAPT, in bits). Strides are signed bytes per row. BLTNEXT = 0 ends the chain (only its bits 21–1 count).

## Data structures

Descriptor (32 bytes, little-endian words; the same layout as `BLTCTRL`…`BLTNEXT`):

| Byte | Word | Register | Byte 3 (bits 31–24) | Byte 2 (23–16) | Byte 1 (15–8) | Byte 0 (7–0) |
|------|------|----------|---------------------|----------------|---------------|--------------|
| +0 | 0 | `BLTCTRL` | MINTERM 7–0 | MASK 2–1 | BCONST 5, IRQ 4, RTL 2, BPP 1–0 | KEY 7–0 |
| +4 | 1 | `BLTBPT` | BIT 2–0 | ADDR[23:16] | ADDR[15:8] | ADDR[7:0] |
| +8 | 2 | `BLTDPT` | BIT 2–0 | ADDR[23:16] | ADDR[15:8] | ADDR[7:0] |
| +12 | 3 | `BLTSIZE` | HEIGHT[31:24] | HEIGHT[23:16] | WIDTH[15:8] | WIDTH[7:0] |
| +16 | 4 | `BLTAPT` | BIT 2–0 | ADDR[23:16] | ADDR[15:8] | ADDR[7:0] |
| +20 | 5 | `BLTSTRIDE` | BSTRIDE[31:24] | BSTRIDE[23:16] | DSTRIDE[15:8] | DSTRIDE[7:0] |
| +24 | 6 | `BLTVALUE` | ASTRIDE[31:24] | ASTRIDE[23:16] | VALUE[15:8] | VALUE[7:0] |
| +28 | 7 | `BLTNEXT` | 0 | ADDR[23:16] | ADDR[15:8] | ADDR[7:0] |

`NAME h–l`: the field in bits h–l of that byte. `NAME[h:l]`: bits h–l of a field wider than the byte (whole-word numbering). Bits not named are reserved: write 0.
<!-- /gen:blitter-desc -->

- A descriptor is the job registers' image: 32 bytes, each word low byte first, at an **even** physical address (bit 0 is dropped). `align 2` (the examples use `align 4`).
- In sjasmplus: `dd ctrl, bpt, dpt` / `dw width, height` / `dd apt` / `dw dstride, bstride, value, astride` / `dd next`.
- **VALUE is in pixel order, not memory byte order:** bits 15–8 go over the even byte, bits 7–0 over the odd byte. An 8 bpp colour c is `c * 0x0101`; 4 bpp `c * 0x1111`; 2 bpp `c * 0x5555`; 1 bpp `0xFFFF` or 0. A 2-byte pattern (a tile-map entry `0x1234`, low byte at the even address) goes in **swapped**: VALUE `0x3412`, and the fill starts at an even address.
- Pixels are packed from the most significant end of each byte (pixel 0 in bits 7–… of the byte).

### MINTERM values (A = `0xF0`, B = `0xCC`, C = `0xAA`)

| MINTERM | D = | Use |
|---------|-----|-----|
| `0xCC` | B | Copy; with BCONST a fill |
| `0xCA` | A ? B : C | Cookie-cut (with MASK = 2: transparent KEY colour) |
| `0x66` | B XOR C | Draw/undraw with the same job |
| `0xEE` | B OR C | Set bits |
| `0x88` | B AND C | Keep bits |
| `0x22` | C AND NOT B | Clear where B set |
| `0x55` | NOT C | Invert |
| `0x00` / `0xFF` | 0 / all ones | Clear / set |
| `0x0A` | A ? 0 : C | Clear through the mask |

With MASK = 0 only bits 7–4 matter. Memory accesses per destination word: B read if the minterm depends on B (or MASK = 2); C read if it depends on C, or at a row's partly covered first/last word; one write. So fill = 1, copy = 2, key cookie-cut = 3.

### Direction (overlapping copies)

| Destination is | Use |
|----------------|-----|
| Left of or above the source | As is |
| Right of it, same rows | RTL; BPT/DPT (and BIT) name the row's last pixel |
| Below it | Bottom row's addresses and negative strides |

A stride of 0 repeats a row. No clipping: trim the rectangle in software (move pointers by k pixels/rows, reduce WIDTH/HEIGHT; 0 = empty job).

## Recipes

Enable the blitter (and the rasteriser):

```asm
        ld      bc,DMACON_P
        ld      a,DMACON_SETCLR_M | DMACON_DMAEN_M | DMACON_BLTEN_M
        out     (c),a
```

Fill a 360 × 288 8 bpp screen at physical `0x020000` with colour 1: one job written into the registers from a 32-byte image, then RUN, then poll.

```asm
SCREEN  equ     0x020000
clear:  ld      bc,BLTSTAT_P
.idle:  in      a,(c)
        rra                             ; BUSY into carry
        jr      c,.idle
        ld      hl,job
        ld      b,high BLTCTRL0_P       ; C stays 0x11: B walks 0x40..0x5F
.next:  ld      a,(hl)
        out     (c),a
        inc     hl
        inc     b
        ld      a,b
        cp      high (BLTCTRL0_P + 0x2000)
        jr      nz,.next
        ld      b,high BLTCMD_P
        ld      a,BLTCMD_RUN_M
        out     (c),a
        ld      b,high BLTSTAT_P
.wait:  in      a,(c)
        rra
        jr      c,.wait                 ; done; A bit 1 = ERR >> 1
        ret

job:    dd      (0xCC << BLTCTRL_MINTERM_B) | BLTCTRL_BCONST_M | (3 << BLTCTRL_BPP_B)
        dd      0                       ; BLTBPT: unused with BCONST
        dd      SCREEN                  ; BLTDPT
        dw      360, 288                ; WIDTH, HEIGHT
        dd      0                       ; BLTAPT
        dw      360, 0                  ; DSTRIDE, BSTRIDE
        dw      0x0101, 0               ; VALUE (colour 1, both bytes), ASTRIDE
        dd      0                       ; BLTNEXT: single job
```

A chain of descriptors in SRAM, started with BLTDESC + START (from `examples/blitter/blitter.asm`). In the program map a Z80 address in `0x2000`–`0xFFFF` is its physical address, so labels can be used directly:

```asm
SCREEN  equ     0x020000
W       equ     360
    MACRO JOB ctl, bpt, dpt, wid, hgt, dstr, bstr, val, nxt
        dd      ctl, bpt, dpt
        dw      wid, hgt
        dd      0                       ; BLTAPT: no mask image
        dw      dstr, bstr, val, 0
        dd      nxt
    ENDM
B8      equ     3 << BLTCTRL_BPP_B
MKEY    equ     2 << BLTCTRL_MASK_B     ; A = (B != KEY); KEY 0 here
MT      equ     1 << BLTCTRL_MINTERM_B

go:     ld      bc,BLTDESC0_P
        ld      a,low job1
        out     (c),a
        inc     b
        ld      a,high job1
        out     (c),a
        inc     b
        xor     a                       ; bits 23-16: 0 in the program map
        out     (c),a
        ld      bc,BLTCMD_P
        ld      a,BLTCMD_START_M
        out     (c),a                   ; returns at once; poll BLTSTAT or take INT_BLT
        ret

        align   4
job1:   JOB     B8|BLTCTRL_BCONST_M|0xCC*MT, 0, SCREEN, W, 288, W, 0, 0x0101, job2
job2:   JOB     B8|MKEY|0xCA*MT|BLTCTRL_IRQ_M, sprite, SCREEN+100*W+164, 16, 16, W, 16, 0, 0
sprite: ds      16*16, 0                ; 16 x 16, 8 bpp, colour 0 transparent
```

Copy with a transparent colour: `MINTERM 0xCA`, MASK = 2, KEY = the transparent colour, BPT the image, BSTRIDE the image's width. Scroll a picture down 8 rows: BPT/DPT at the last source/destination rows, both strides −W (`dw -360`). Scroll right: RTL with BPT/DPT at each row's last pixel.

Interrupt handler body for source 4 (shared with the rasteriser):

```asm
blt_isr:
        push    af
        push    bc
        ld      bc,DMXINT_P
        in      a,(c)                   ; BLT bit 0, RAS bit 1
        out     (c),a                   ; W1C: clear what was seen
        ; ... act on A ...
        pop     bc
        pop     af
        ei
        reti
```

## Pitfalls and limits

- **SRAM only, physical addresses.** Pointers and BLTNEXT are 22-bit physical: MMU page × `0x2000` + (Z80 address AND `0x1FFF`). The register page, palettes, boot ROM and ports are unreachable; `0x7F0000` wraps into SRAM. No range check: a wrong address silently overwrites SRAM (a runaway write over the monitor's pages `0x0FE`/`0x0FF` loses the console; see system.md on board wedges). On the KS2 (2 MB) bit 21 is ignored: `0x200000` mirrors `0x000000`.
- Writes to job registers and BLTDESC are **ignored while BUSY**: always wait for BUSY = 0 before setting up the next job.
- MASK = 1 (mask image) is an **error on the KS2**; MASK = 3 is always an error. Errors are found before anything is written: ERR and DMXINT.BLT set, chain ends.
- Reserved bits are silently dropped, not errors: a version-1 job layout gives a wrong picture, not ERR.
- VALUE byte order (above) is the usual mistake: a 2-byte fill pattern must be swapped.
- WIDTH and HEIGHT are 16 bits (0 = empty job). Strides are signed 16-bit (±32,767). A linear copy longer than 65,535 bytes: rows of equal WIDTH/BSTRIDE/DSTRIDE, or a chain.
- The CPU and the blitter share SRAM without locks: don't touch an area a job is writing. A CPU write made before the START/RUN write is seen by the job.
- The blitter and the rasteriser can run at once; where their destinations overlap the write order is unspecified. Wait for one before the other draws over it.
- A BLTDESC read captures: read `BLTDESC0` first, then 1 and 2 (an interrupt handler reading another capturing register in between spoils it).
- The copper writes these registers only with MOVEF (offsets above `0x0EF`); its WAIT with the B bit waits until both the blitter and the rasteriser are idle ([copper.md](copper.md)).
- **Speed, measured on the KS2** (examples/blitter/speed.asm, screen on / off): fill 22.3 / 24.9 MB/s; copy of 104 KB 7016 / 6242 µs (about 14.8 MB/s on); a 32×32 key draw 105 / 93 µs; 8 empty descriptors 22 / 21 µs. `LDIR` is about 0.95 MB/s at 20 MHz; the CPU runs on at full speed meanwhile. A descriptor load is 16 reads (about 1 µs).
