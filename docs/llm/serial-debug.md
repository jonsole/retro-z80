# USB serial, debug unit, SD card

> retro-z80 reference for AI models writing Z80 code. Register tables between `<!-- gen:NAME -->` markers are generated from `fpga/regmap.def` by `python3 tools/llm_docs.py serial-debug`: never edit them by hand. Every ```asm block assembles on its own (`python3 tools/llm_docs.py --asm serial-debug`); general rules are in [system.md](system.md).

**Built on the KS2:** USB serial (FT232H on the accelerator header; the bridge runs over it) and the debug unit, yes. **Not built:** the SD card controller (registers `0x58`–`0x5B`, `0x5D`–`0x5F` read `0xFF`, writes ignored; ROM functions `0x12`–`0x14` are not there) and the I2C master (`0x78`–`0x7B`, read `0xFF`).

## What it does

**Serial:** a byte link to the PC through 2 KB receive and 2 KB transmit FIFOs, hardware flow control both ways, never a lost byte, the CPU never waits. The PC's control commands (BREAK → NMI, RESET, UPLOAD, KEY → PS/2 byte) are taken out of the stream in hardware. The bridge (`tools/rz80_bridge.py`), the monitor console and program uploads all use this link.
**Debug unit:** single step, 4 breakpoints (address, optional page), 2 watchpoints (address + mask, read/write, memory or I/O), all raising the NMI into the boot ROM's debug stub. The bridge's `set_breakpoint`, `set_watchpoint`, `step` use it.

## Enable

| What | State a program inherits | Notes |
|------|--------------------------|-------|
| SERCON | `EN | CTLEN | TXDROP` (`0x0B`) set by the boot ROM | Hardware reset value is `0x02` (CTLEN only) |
| Serial interrupts | Off (SERIRQEN 0, SERLEVEL 0, SERTIME 0) | Source 15 SERIAL ([interrupts-timers.md](interrupts-timers.md)) |
| Debug unit | Driven by the stub; all breakpoints off unless the bridge set them | Do not write it from a program |

| `0x54` | `0x5400` | `SERLEVEL` | 1 | RW | RXLEVEL 7–4, TXLEVEL 3–0 |

| `0x57` | `0x5700` | `SERIRQEN` | 1 | RW | TXOVF 3, TXREADY 2, RXTIMEOUT 1, RXREADY 0 |
| `0x5C` | `0x5C00` | `SERDROP` | 1 | R,F | – |
<!-- /gen:serial -->

- SERDATA is also port `0x53` with any high byte (`SERDATA_PORT`): `IN A,(0x53)`, `OUT (0x53),A`, `INIR`, `OTIR` work.
- SERSTAT0 = TXSPACE (room, 0–255, 255 = 255 or more); SERSTAT1 = RXCOUNT (waiting, 0–255 saturating). Two independent live bytes, no capture.
- Reading SERDATA when empty returns `0x00` and takes nothing: check RXCOUNT first. Writing when full loses the byte (TXOVF), or with TXDROP pushes out the oldest byte and counts it in SERDROP (read clears).
- SERCON bits 4 (RXFLUSH) and 5 (TXFLUSH) are strobes (write 1, read 0). CTLLOCK (2) can be set, not cleared, by software.
- SERLEVEL: RXLEVEL (7–4), TXLEVEL (3–0); code 0 = off, n = 1–12 means 2^(n−1) bytes, 13–15 as 12.
- SERTIME: RXTIMEOUT after 16(n−1)–16n µs without traffic; 0 = off.
- SERIRQ: RXREADY (0, live: RXCOUNT ≥ RXLEVEL), RXTIMEOUT (1, sticky W1C), TXREADY (2, live: TXSPACE ≥ TXLEVEL), TXOVF (3, sticky W1C). SERIRQEN same layout.

### PC control commands (in the byte stream, while CTLEN or CTLLOCK)

| Bytes from the PC | Effect |
|-------------------|--------|
| `C0 01 FE` | BREAK: NMI (if NMICON.USBEN) → the monitor / debug stub |
| `C0 02 FD` | RESET (RESETWHY.USB) |
| `C0 03 FC` | UPLOAD: reset into the boot ROM's loader |
| `C0 04 b ~b` | KEY: byte b as if from the PS/2 keyboard |
| `DB DC` / `DB DD` | Data bytes `C0` / `DB` (the PC tools escape them) |

With CTLEN and CTLLOCK clear, every byte (`C0`, `DB` too) is data, and the PC must not escape.

- Port = register × 256 + `0x02` (`DBGPAGE`); register page offset `0x0200` + register (`REGS_DBGPAGE`). `0x3D`–`0xFF` reserved.
- Live only from the first M1 after a `RETN` to the next NMI's entry; never while NMICTL.INNMI. DBGCTL.LIVE reads 1 while live; writing 0 turns it off.
- DBGCTL.STEP: one instruction after the next `RETN`, then an NMI; cleared by hardware. STEPINT lets /INT in during the step.
- Breakpoint: compared on instruction-starting opcode fetches; stops **before** the instruction (works in ROM; nothing written into memory). PAGEEN also compares the window's read page.
- Watchpoint: MASK bit 1 = compared (reset `0xFFFF`); READ, WRITE, IO select. Stops **after** the instruction; DBGHITADDR/DATA/KIND keep the first matching access.
- DBGSTAT: which asked for the NMI, sticky W1C.

## Recipes

Send A (polled):

```asm
putc:   ld      e,a
.wait:  ld      bc,SERSTAT0_P           ; TXSPACE
        in      a,(c)
        or      a
        jr      z,.wait                 ; no room yet
        ld      a,e
        out     (SERDATA_PORT),a
        ret
```

Wait for a byte (polled):

```asm
getc:   ld      bc,SERSTAT1_P           ; RXCOUNT
        in      a,(c)
        or      a
        jr      z,getc
        in      a,(SERDATA_PORT)
        ret
```

Bulk: read everything waiting with `INIR`, send a block with `OTIR` (21 T a byte, about 0.95 MB/s at 20 MHz):

```asm
        ld      hl,buf
        ld      bc,SERSTAT1_P
        in      a,(c)                   ; RXCOUNT, saturates at 255: fits B
        or      a
        jr      z,.send
        ld      b,a
        ld      c,SERDATA_PORT
        inir                            ; B is the count, not a register number, on port 0x53
.send:  ld      hl,msg
        ld      bc,SERSTAT0_P
        in      a,(c)                   ; TXSPACE
        cp      msglen
        jr      c,.send                 ; wait for room for the whole block
        ld      b,msglen
        ld      c,SERDATA_PORT
        otir
        ret
msg:    db      "hello", 13, 10
msglen  equ     $-msg
buf:    ds      255
```

Take the link for the program and give the console back (Example 7-1). `RST 28h` function `0x0E` CONMODE: bit 0 screen output, bit 1 serial output, bit 2 keys from keyboards, bit 3 keys from serial:

```asm
        ld      a,0x05                  ; screen out, keyboard in; the link is the program's
        rst     0x28
        db      0x0E                    ; CONMODE: A = the old mode
        ld      (oldmode),a
        ; ... own SERDATA traffic ...
        ld      a,(oldmode)
        rst     0x28
        db      0x0E                    ; console as it was
        ret
oldmode: db     0
```

Serial interrupt on every received byte (handler at `TABLE+2*INT_SERIAL`, IM 2 set up as in [interrupts-timers.md](interrupts-timers.md)):

```asm
        ld      bc,SERLEVEL_P           ; RXLEVEL code 1 (1 byte), TXLEVEL code 1
        ld      a,(1<<SERLEVEL_RXLEVEL_B)|(1<<SERLEVEL_TXLEVEL_B)
        out     (c),a
        ld      bc,SERIRQEN_P           ; RXREADY only; TXREADY only while data is queued
        ld      a,SERIRQEN_RXREADY_M
        out     (c),a
        ld      bc,INTENA0_P+(INTR_SERIAL<<8)
        ld      a,INTENA_SETCLR_M|(1<<INTB_SERIAL)
        out     (c),a
        ld      bc,INTCON_P
        ld      a,INTCON_MASTER_M
        out     (c),a
        ei
ser:    push    af                      ; handler: RXREADY is live, so reading drops it
        push    bc
.more:  ld      bc,SERSTAT1_P
        in      a,(c)
        or      a
        jr      z,.done
        in      a,(SERDATA_PORT)        ; take a byte (store it somewhere)
        jr      .more
.done:  pop     bc
        pop     af
        ei
        reti
```

## Pitfalls and limits

- **Do not clear SERCON.CTLEN or EN** in a program that is to be debugged or reloaded: with CTLEN clear (and no CTLLOCK) the PC's BREAK, RESET and UPLOAD are ignored and the bridge loses the board until reset/power-cycle. Write SERCON whole, keeping `EN|CTLEN` (and TXDROP).
- The link is shared with the bridge. While the bridge is **attached** (after `launch`/`attach`), the stub turns off the console's serial side: ROM PUTC/PUTS output goes to the screen only (use `screen_capture`), and raw bytes a program writes to SERDATA show in the bridge as program output. While **not attached**, `read_console` returns the monitor console's text and `send_console` types into it.
- A program that reads SERDATA steals bytes the bridge's frames need; only read the link when the program owns it, and never while debugging over it.
- With nobody reading on the PC, sends pile up; without TXDROP the FIFO fills and polling loops hang. The ROM sets TXDROP; keep it for debug output.
- Raw terminals send unescaped bytes: `C0`/`DB` in binary data are taken as commands/escapes. Use the PC tools (`rlink.py`, the bridge), which escape.
- RXREADY/TXREADY are levels: a handler must drain the FIFO, or turn TXREADY's enable off when nothing is queued, or it is re-entered for ever.
- Debug unit: a program must not write DBG registers while the bridge is attached; the bridge owns all 4 breakpoints and 2 watchpoints (shared with VS Code). Breakpoints compare CPU addresses: use `page` for a banked window.
- Watchpoints stop after the instruction; the stop PC is the next instruction.
- SD card, I2C (RTC, DDC): not built. Do not wait on SDSTAT.BUSY or I2CSTAT.BUSY: they read `0xFF` (busy for ever).
